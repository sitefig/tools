GraphQL Query Formatter

Paste a GraphQL query, mutation or fragment on one line or many and get it back with tidy two-space indentation and one field per line.

Use the tool

Why this tool exists

GraphQL queries often arrive minified from a network tab, a log line or a code string, with commas and fields all run together. Reading nested selections like user { posts { edges { node } } } on one line is hard, and reviewing a change to it is worse.

This formatter tokenises the document and rebuilds it with one selection per line, aligned braces, tidy arguments and variable definitions kept on the operation line. It keeps comments and block strings. It does not check your query against a schema, so it works for any API, and what you paste stays in your browser.

How to use it

  1. Paste a GraphQL query, mutation or fragment into the input.
  2. Read the formatted result, indented with two spaces per level.
  3. Copy it back into your code or API client.

Frequently asked questions

Does it validate the query against a schema?

No. It only checks that braces are balanced and then reformats the text. A field that does not exist in your schema will not be flagged.

What happens to commas?

GraphQL treats commas as whitespace, so the formatter drops them between selections. Arguments and variable lists are kept on one line with spacing normalised.

Are comments and descriptions kept?

Yes. Hash comments get their own line at the current indent, and triple-quoted block strings are preserved as single tokens.

Can it format a schema definition?

It is designed for operations and fragments. Schema definition language may format acceptably in simple cases, but nothing is guaranteed for complex type definitions.
