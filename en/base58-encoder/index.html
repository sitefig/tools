Base58 Encoder / Decoder

Encode text or hex bytes using the Bitcoin Base58 alphabet, or decode a Base58 string back to text or hex. No checksum is added or checked.

Use the tool

Why this tool exists

Base58 drops the look-alike characters 0, O, I and l from Base64, so values are easier to read aloud and copy by hand. It is used for Bitcoin addresses, Solana public keys, IPFS CIDv0 hashes and many other identifiers.

When you are debugging one of these, you often need to see the raw bytes behind a string, or turn a hex value into the string form. This tool converts both ways using big-integer arithmetic and keeps leading zero bytes as leading ones, which is how Base58 preserves them. It does not add the four-byte checksum used by Base58Check, so it will not validate a Bitcoin address by itself.

How to use it

  1. Choose encode or decode, and whether the bytes are text or hex.
  2. Paste your text, hex bytes or Base58 string.
  3. Copy the converted result.

Frequently asked questions

Does it handle Base58Check?

No. Base58Check adds a version byte and a four-byte checksum around the payload. This tool converts the plain bytes only, so a decoded Bitcoin address will include those extra bytes.

Why do leading zero bytes become ones?

The Base58 alphabet starts with the digit 1 for the value zero. Each leading zero byte in the input is written as a leading 1 so that the length survives a round trip.

Which alphabet is used?

The Bitcoin alphabet: digits 1 to 9, uppercase without I and O, and lowercase without l. Flickr and Ripple use different orderings, which this tool does not support.

What happens with a bad character?

Decoding stops with an error naming the invalid character, for example a zero or a lowercase L, so you can spot a transcription mistake.
