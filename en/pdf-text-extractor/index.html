PDF Text Extractor with Layout (Subset Fonts)

Reads the text layer of a PDF using each font's Unicode map, so it works on files from Word, Chrome, LaTeX and InDesign where simple extractors return nothing. Output is plain text with page markers.

Use the tool

Why this tool exists

Most modern PDFs store characters as glyph numbers in subset fonts. The readable text is only recoverable through a ToUnicode map inside the file, and a tool that ignores it returns garbage or nothing. This one parses those maps, the font widths and the page geometry, then groups glyphs into lines by position.

The layout option pads gaps with spaces so columns line up in plain text. Limits: text runs left to right and top to bottom, so a two-column page reads straight across the columns; rotated text is flagged rather than placed; scanned pages have no text layer, and the PDF OCR tool handles those. Encrypted files must be unlocked first.

How to use it

  1. Choose a PDF.
  2. Optionally enter a page range such as 1-3,5.
  3. Tick "keep gaps between columns" for tables or forms.
  4. Press Run, copy the text or download the .txt file.

Frequently asked questions

Why does a PDF give no text?

The pages may be scans, which are pictures of text. Run the OCR tool first.

Why is the order wrong in two-column pages?

Lines are read straight across the page. Copy one column at a time with a page range, or use layout mode to see the columns separated by spaces.

Does it send my file anywhere?

No. The file is parsed in your browser.

It says some glyphs had no Unicode mapping. What now?

Those characters come from fonts without a usable text map, often symbols or custom encodings. They are skipped.
