Chain-of-Thought Prompt Builder

Enter a task and choose a reasoning pattern, such as zero-shot chain of thought, plan-and-solve, step-back or tree-of-thought, then pick the answer format and copy the finished prompt.

Use the tool

Why this tool exists

Asking a model to think before answering often improves results on maths, logic and multi-step questions, but the wording matters, and the different published patterns do different things. Plain let's think step by step is not the same as asking for a plan first, or for several independent attempts that are then compared.

This builder wraps your task in the pattern you pick, with a final answer format so the reasoning stays separate from the result you need to parse. It saves rewriting the same scaffolding for each experiment and makes it easier to compare patterns on identical tasks. Reasoning models may do this internally already, so test whether the extra structure helps. The prompt is built in your browser.

How to use it

  1. Type or paste the task or question for the model.
  2. Choose a reasoning technique from the list.
  3. Pick an answer format, and set the number of attempts or panel members where the pattern needs it.
  4. Copy the prompt and test it with your model against your usual inputs.

Frequently asked questions

Does chain of thought always help?

No. It tends to help on multi-step reasoning and can add cost and length on simple questions. Some newer models reason internally, so extra instructions may add nothing. Test with your own examples.

What is the difference between the techniques?

Zero-shot CoT asks for step-by-step thinking. Plan-and-solve asks for a plan first. Step-back asks for general principles before the details. Self-consistency and tree-of-thought use several attempts or viewpoints that are compared.

How do I get a clean final answer?

Choose an answer format that puts the result in a marked place, such as a tagged final answer. Then your code can read that part and ignore the reasoning above it.

Tools often used together

  • Few-Shot Prompt FormatterFormat input => output example pairs as a few-shot prompt: plain labels, XML tags, Markdown, or ready-to-send OpenAI / Anthropic message JSON. Use \n inside an example for line breaks.
  • System Prompt XML BuilderTurn a plain outline of prompt sections into a well-structured, XML-tagged system prompt (the structure recommended for Claude and also effective for other models): role, context, instructions, constraints, examples (grouped in <examples>), output format and a document/input placeholder, with consistent tag names, escaped content where needed and an approximate token count.
  • Prompt Linter / Optimizer ChecklistRule-based review of an LLM prompt (no model is called): checks for role, task, output format, constraints, examples, structure, vague or hedging wording, shouting, negative-only instructions, unfilled placeholders, repeated sentences and length, then lists concrete fixes with a score.
  • LLM Context Window ShrinkerShrink text to fit a token budget: keep head, tail, both ends, drop duplicate lines, or keep the most informative sentences in original order (frequency-based extractive summary). Token counts are estimates (characters / ratio), not a real tokenizer.
  • Prompt Template Variable FillerFill {{variables}} in a prompt template from KEY=VALUE lines or JSON; reports missing and unused variables.
  • System Prompt FormatterRestructure a free-form system prompt into labelled sections (role, context, instructions, constraints, output format, examples) using XML tags or Markdown headings. Sections are detected from existing headings/tags or, failing that, by keyword heuristics per paragraph or bullet; review the result, it does not rewrite wording.
