JSON Schema Generator

Infer a draft-07 JSON Schema from a sample document. Choose whether keys are required, forbid extra properties, and detect string formats like email or date-time.

Use the tool

Why this tool exists

A JSON Schema documents what your data should look like and lets other tools check it, but writing one from scratch is slow. A good first draft from a real example saves most of the typing, and you can then tighten it by hand.

Paste a sample and the tool works out types for every value, merges array items, and lists required keys. With format detection on, strings that look like email addresses, dates, date-times, UUIDs or URLs get a matching format. The strict option adds additionalProperties false so unknown keys are rejected. Because the schema comes from one sample, treat it as a draft and add limits yourself. You can test the result with the JSON Schema Validator. Nothing is uploaded.

How to use it

  1. Paste a representative JSON sample into the input box.
  2. Tick Mark keys required if every key seen should be mandatory.
  3. Tick additionalProperties: false for a strict schema, and Detect formats for email, date and similar strings.
  4. Copy the draft-07 schema into your project.

Frequently asked questions

Which JSON Schema version does it produce?

Draft-07. The generated schema begins with the draft-07 $schema URL, which most validators, editors and code generators understand, so you can use it straight away.

How are optional properties decided?

When array items are merged, keys missing from some items are left out of required. If you untick the required option, no property is marked required at all.

How reliable is format detection?

It looks at the sample value only, using simple patterns for formats such as email, date, date-time and UUID. A string that happens to look like a date may get a format you did not intend.

What should I add by hand?

Anything a sample cannot tell: minimum and maximum values, string lengths, patterns, enums and descriptions. Add them, then check some real documents with the schema validator.
