SQLite Database Viewer (.sqlite, .db)

Look inside a SQLite database from an app, a phone backup or a download without installing a database tool.

Use the tool

Why this tool exists

The page reads the file format directly: header, page size, text encoding, the schema table and the b-tree pages of every ordinary table, including cells that spill onto overflow pages. Columns are named from the CREATE TABLE statement and INTEGER PRIMARY KEY columns show the rowid. Results were compared with Python's sqlite3 on a database with 1,500 rows, big text values and blobs.

It is read-only and has no SQL engine. WITHOUT ROWID tables, virtual tables and index b-trees are listed but not read. Files are processed in memory, so very large databases may be slow.

The file is read in your browser and is not uploaded anywhere.

How to use it

  1. Choose a .sqlite, .sqlite3 or .db file.
  2. Set how many rows to show per table.
  3. Read the schema and sample rows.
  4. Use the CSV and SQL tools to query exported data.

Frequently asked questions

Is my database uploaded?

No. It is read in your browser.

Can I run SQL?

No, this is a viewer. Export tables and use the SQL-on-CSV tool for queries.

Why is a table not shown?

It may be WITHOUT ROWID or virtual, which this reader does not decode.

Is my data sent anywhere?

The file is read in your browser and is not uploaded anywhere.

Tools often used together

  • SQL on CSV / JSON (in-browser SQL)Run SQL against pasted CSV or JSON. Box 1: tables separated by a line of ---, each CSV (first row = header) or a JSON array of objects, optionally starting with "-- name: users"; they become t1, t2, ... (and the name). You can also put CREATE TABLE / INSERT statements in either box. Box 2: statements separated by ;. Supported: SELECT with expressions, aliases, DISTINCT, WHERE (AND OR NOT, comparisons, LIKE, GLOB, IN, BETWEEN, IS [NOT] NULL, EXISTS), INNER/LEFT/RIGHT/FULL/CROSS JOIN with ON or USING, GROUP BY/HAVING, COUNT SUM AVG MIN MAX TOTAL GROUP_CONCAT (DISTINCT ok), ORDER BY (aliases, ordinals, NULLS FIRST/LAST), LIMIT/OFFSET, subqueries (FROM, IN, EXISTS, scalar, correlated), WITH (non-recursive), UNION [ALL]/INTERSECT/EXCEPT, CASE, CAST, string and math functions, CREATE TABLE [AS], CREATE VIEW, INSERT, UPDATE, DELETE, DROP. Differences from SQLite: "/" is always true division, numeric-looking text compares as a number, empty CSV cells are NULL, no constraint enforcement (PRIMARY KEY/UNIQUE/NOT NULL), no window functions, recursive CTEs, triggers or date functions. Output is a text table plus CSV; nothing leaves your browser.
