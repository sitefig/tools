Terraform / HCL Formatter

Paste Terraform or other HCL and get consistent two-space indentation with the equals signs aligned in runs of attribute lines, in the style of terraform fmt.

Use the tool

Why this tool exists

Terraform code pasted from a blog, a chat or an older module rarely follows the layout that terraform fmt produces. Reviewers then spend time on whitespace instead of logic, and a CI check that runs fmt fails the pull request. If you are on a machine without Terraform installed, you cannot fix it on the spot.

This formatter handles the two things people see most: nesting indentation and alignment of consecutive attributes. Heredoc bodies are copied exactly. It is text-based and approximate, so treat terraform fmt as the final word in your pipeline.

How to use it

  1. Paste your Terraform or HCL code into the input.
  2. Read the formatted output, with nested blocks indented by two spaces.
  3. Copy it back into your .tf file.

Frequently asked questions

Is the output identical to terraform fmt?

It follows the same main rules, indentation by depth and aligned equals signs, but it is a text-based approximation. Edge cases such as complex expressions may differ, so run terraform fmt in CI as the reference.

What happens to heredocs?

Everything between a heredoc start such as EOT and its closing marker is copied unchanged, so embedded scripts and JSON policies keep their original spacing.

Does it validate my configuration?

No. It does not parse the language or check resource arguments, provider schemas or references. Use terraform validate for that, and terraform plan to see what a change would do.

Are comments kept?

Yes. Hash and double-slash comments stay on their lines and are indented with the block they sit in. Brackets inside strings and comments are ignored when counting depth.

Tools often used together

  • Terraform HCL to JSONParse Terraform / HCL2 configuration into JSON. Labeled blocks nest by label (resource.aws_instance.web), unlabeled blocks become arrays, non-literal expressions (references, function calls, conditionals, for expressions) are kept as "${...}" strings as in the Terraform JSON syntax. Comments and heredocs are handled; dynamic blocks are not expanded.
  • Terraform HCL to YAMLParse Terraform / HCL2 configuration and print it as YAML using the same structure as the Terraform JSON syntax (labeled blocks nested, unlabeled blocks as lists, expressions as "${...}" strings).
  • YAML / JSON to Terraform HCLTurn YAML or JSON in Terraform JSON-syntax shape (resource: {type: {name: {...}}}, variable:, output:, locals:, provider:, terraform:) into HCL. Strings that are a single "${...}" expression are written unquoted, lists of mappings become repeated nested blocks, known block names (lifecycle, connection, ...) become blocks, other mappings (tags, etc.) stay attribute maps. Output is aligned like terraform fmt.
  • Terraform AWS ScaffolderScaffold providers, remote state, VPC, S3 bucket and EC2 instance blocks (formatted like terraform fmt).
  • YAML FormatterRe-indent and normalise YAML (comments are not preserved; anchors are expanded).
  • JSON FormatterPretty-print JSON with custom indent and optional key sorting; errors show line and column.
