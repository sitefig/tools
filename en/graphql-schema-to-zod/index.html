GraphQL Schema to Zod

Converts GraphQL SDL types, inputs, enums and unions into Zod schemas, with .nullable() and .optional() applied, lists as z.array and recursive types wrapped in z.lazy.

Use the tool

Why this tool exists

GraphQL checks types on the server, but data coming out of a client, a form or a webhook is not covered by that. Zod lets you validate those values in TypeScript, and your GraphQL schema already describes the shapes. Rather than writing every z.object twice, paste the SDL and get matching schemas. Enums become z.enum, unions become z.union, lists become z.array, nullable fields get .nullable() and recursive types use z.lazy so they do not fail on circular references. Custom scalars become z.string(), which you can edit to something stricter. Operation roots are skipped unless you include them. Your schema is processed in your browser.

How to use it

  1. Paste your GraphQL SDL into the input box.
  2. Tick "Include Query / Mutation / Subscription" only if you need those roots.
  3. Copy the Zod module and refine custom scalars such as dates.

Frequently asked questions

How are nullable and optional fields marked?

Nullable fields get .nullable() or .optional() depending on how the type is used, and fields marked non-null are required. Lists become z.array, so each element is validated as well.

How are recursive types handled?

Types that refer to themselves, directly or through others, use z.lazy so Zod can build the schema without a reference error.

What happens to custom scalars?

They become z.string(). Replace them with a more precise validator, for example a date or JSON schema, where the data needs it.

Does it generate TypeScript types too?

It outputs the Zod schemas. Use z.infer in your code, or the GraphQL to TypeScript tool on this site if you want plain interfaces.

Tools often used together

  • GraphQL Schema to TypeScriptConvert GraphQL SDL (type, input, interface, enum, union, scalar, descriptions) into TypeScript interfaces and types. Interface fields are inlined into implementing types; nullable output fields become "T | null", nullable input fields become optional. Query/Mutation root types are skipped unless enabled; field arguments are ignored.
  • TypeScript Interface to Zod SchemaConvert TypeScript interfaces, type aliases and enums into Zod schemas (z.object, z.enum, z.union, z.tuple, z.record, optional/nullable, descriptions from JSDoc) plus inferred types. Same TypeScript subset as the TypeScript to JSON Schema tool.
  • JSON Schema to ZodTurn a JSON Schema (draft-07 / 2020-12 subset: types, formats, bounds, enum/const, anyOf/oneOf/allOf, $ref to $defs) into Zod source code.
  • Zod Schema to TypeScript TypeStatically convert Zod schema source (z.object, z.string().min(), z.enum, z.union, z.array, z.record, optional/nullable/nullish, extend/merge, describe) into the equivalent TypeScript types, i.e. what z.infer would produce. The code is parsed, never executed. .transform() outputs and custom refinements are not inferable.
  • JSON to GraphQL Schema (SDL)Infer GraphQL type definitions from a JSON sample: nested objects become types, arrays become lists, keys missing or null in some array items become nullable, "id" becomes ID, integers vs floats are told apart.
  • JSON to Zod SchemaGenerate a Zod schema (and inferred type) from a JSON sample.
