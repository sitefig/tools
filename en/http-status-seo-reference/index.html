HTTP Status Codes: What Each Means for SEO

A searchable list of common HTTP status codes with a plain note on what each one means for Google Search: whether the page can be indexed, how crawling reacts and how strong a redirect signal is.

Use the tool

Why this tool exists

Most status code lists describe the protocol. This one describes the effect on search. A 301 and a 302 both move a visitor, but Google reads a 301 as a strong hint that the new URL should be the indexed one and a 302 as a weak hint. A 404 and a 410 look different to a developer but Google handles them alike.

The notes come from Google Search Central's documentation on status codes and site moves, read in October 2026. Codes that Google does not document are marked as not covered, and the note says it is an assumption. Google can change its handling, so check the source for anything important.

How to use it

  1. Type a code, a class such as 3xx, or a word such as redirect.
  2. Read the note under each code.
  3. Leave the box empty to list every code.

Frequently asked questions

Does a 410 remove a page faster than a 404?

Google handles them the same way. Use 410 to say the removal is deliberate, but do not expect a faster result.

Is a 302 bad for SEO?

No, it is the right code for a real temporary move. A 302 left in place for a permanent move is the problem, because it sends a weak signal.

Why does 429 appear next to server errors?

Google treats 429 as a sign of server overload, so crawling slows down, as it does for 5xx errors.

Where do these notes come from?

Google Search Central pages on HTTP status codes and on site moves. Codes without a source are marked.
