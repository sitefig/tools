Caddyfile Generator

Build a Caddyfile site block for a reverse proxy, static file server, single-page app, PHP-FPM site or redirect, with compression, security headers, logging and an optional www redirect.

Use the tool

Why this tool exists

Caddy is popular because it gets HTTPS certificates automatically and has a short configuration language. Even so, the common recipes are easy to forget: how a single-page app falls back to index.html, how to hand PHP to FPM, or which security headers to add.

Enter the site address and choose a mode. Reverse proxy takes an upstream such as localhost:3000, file server and SPA take a root folder, PHP uses php_fastcgi with a socket path you should check, and redirect takes a target URL. You can add encode zstd gzip, a header block, access logging, tls internal for local certificates and a global ACME email. The headers are sensible defaults, not a full security policy. Nothing is uploaded.

How to use it

  1. Enter the site address, for example example.com.
  2. Choose a mode and enter the upstream, root folder or redirect target.
  3. Tick compression, security headers, logging and www redirect as needed.
  4. Copy the Caddyfile, then run caddy validate and reload.

Frequently asked questions

Does Caddy handle HTTPS automatically?

Yes, for public domain names, Caddy obtains and renews certificates by itself. Use tls internal for local names, where it issues certificates from its own authority instead.

How does the SPA mode work?

It serves files from the root folder and uses try_files to fall back to /index.html for unknown paths, so client-side routes work when someone reloads the page.

Is the PHP socket path correct for my system?

The tool uses unix//run/php/php-fpm.sock as a common default. Package names and versions vary, so confirm the real socket path on your server.

What does the www redirect do?

It adds a second site block for www.yourdomain that redirects permanently to the bare domain, keeping the path and query.
