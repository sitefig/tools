JSON Pointer Tester (RFC 6901)

Paste a JSON document and a list of JSON Pointers to see the value each one points to, its tokens and its canonical escaped form, or the reason it fails.

Use the tool

Why this tool exists

JSON Pointer is the addressing syntax behind JSON Schema references, OpenAPI $ref values and JSON Patch paths. It looks simple, but a few rules cause real bugs: keys that contain a slash or a tilde must be escaped, array indexes cannot have leading zeros, and the empty string points to the whole document.

Paste a document on one side and your pointers on the other, one per line, and see exactly what each resolves to. Errors name the cause, such as a missing key or an index out of range. The tool also understands URI fragment form starting with a hash and decodes percent escapes first. It evaluates pointers only and cannot modify the document.

How to use it

  1. Paste the JSON document into the first box.
  2. Enter pointers in the second box, one per line, such as /users/0/name.
  3. Read the value, tokens and canonical form for each pointer.

Frequently asked questions

How do I address a key containing a slash?

Write the slash as ~1 and a tilde as ~0. The key a/b becomes /a~1b, and m~n becomes /m~0n. The tool shows the canonical escaped path for each pointer.

What does the empty pointer mean?

An empty string refers to the entire document, and a lone slash refers to a key that is the empty string. Both are valid and have different results.

Is the dash token supported in arrays?

The dash means the position after the last element and is only meaningful when adding in JSON Patch. When reading, it fails with an error, as in the standard.

Is this the same as JSONPath?

No. JSON Pointer addresses exactly one location with slash-separated tokens. JSONPath is a query language with wildcards and filters; use the JSONPath tester for that.
