Screen Info

See what your browser reports about your display: resolution, viewport size, pixel ratio, colour depth, touch points, orientation and media features.

Use the tool

Why this tool exists

Designers and developers often need to know exactly what a device reports: the viewport width for a breakpoint, the pixel ratio for choosing image sizes, or whether a screen is wide-gamut or touch-enabled. Support staff ask users for the same numbers when a layout looks wrong. Reading them out of devtools is awkward on a phone.

This page lists the values the browser exposes: screen resolution in CSS pixels, an approximate physical resolution, available area, viewport size, device pixel ratio, colour and pixel depth, orientation, maximum touch points, pointer type, hover capability, wide gamut, HDR, dark mode and reduced motion preference. It updates when you resize or rotate. Everything is read locally from your browser, and nothing is sent anywhere.

How to use it

  1. Open the page on the device you want to check.
  2. Read the values in the list.
  3. Resize the window or rotate the device and watch the numbers update.
  4. Copy the values into your bug report or design notes.

Frequently asked questions

What is the device pixel ratio?

It is the number of physical pixels per CSS pixel. A ratio of 2 means each CSS pixel is drawn with a 2 by 2 block, which is why high-density screens need larger images to look sharp.

Why is the physical resolution approximate?

It is calculated by multiplying the CSS resolution by the pixel ratio. Browser zoom, scaling settings and rounding can make this slightly different from the true panel resolution.

What is the difference between screen and viewport?

The screen is the whole display. The viewport is the visible area for the page inside the browser window, excluding toolbars and scrollbars. Breakpoints respond to the viewport, not the screen.

Why does it say hover is not available?

Touch-only devices usually report no hover capability, because there is no pointer that can hover. This helps sites decide whether to rely on hover menus.
