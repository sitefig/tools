Base64URL Encoder / Decoder

Convert text to URL-safe Base64 using minus and underscore with no padding, or decode Base64URL strings, and standard Base64, back to readable text.

Use the tool

Why this tool exists

Standard Base64 contains plus, slash and equals signs, which all have special meanings in URLs and filenames. The URL-safe variant in RFC 4648 swaps them for minus and underscore and normally drops the padding. You meet it in JWT segments, PKCE challenges, signed URLs and many API tokens.

When a token will not decode in a plain Base64 tool, or a value breaks in a query string, the cause is often this alphabet difference. This tool encodes UTF-8 text to Base64URL and decodes it again, accepting standard Base64 on input too. Decoding fails with a clear message when the data is not valid UTF-8 text, so binary payloads need a different tool.

How to use it

  1. Pick encode or decode.
  2. Paste your text, or the Base64URL or Base64 string, into the input.
  3. Copy the result. Encoded output has no padding characters.

Frequently asked questions

How is Base64URL different from Base64?

It uses minus instead of plus and underscore instead of slash, and usually omits the trailing equals padding. The underlying bytes are identical, only the characters differ.

Can it decode a JWT?

You can paste one segment at a time, header or payload, and read the JSON. For a whole token with claims and expiry, use a JWT decoder, which splits and formats it for you.

Why does decoding report an error?

The input holds characters outside the Base64 alphabets, or its length is impossible for Base64. The decoder also fails if the bytes are not valid UTF-8 text, such as a raw key.

Is padding required?

No. The decoder adds any missing padding itself, so strings with or without trailing equals signs both work. The encoder always leaves the padding off.
