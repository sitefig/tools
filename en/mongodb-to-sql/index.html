MongoDB Query to SQL

Translates MongoDB shell queries into SQL: find with operators like $in, $gt and $or, projection, sort, skip and limit, inserts, updates, deletes and simple aggregate pipelines for PostgreSQL, MySQL or SQLite.

Use the tool

Why this tool exists

People moving between document and relational databases keep running into the same translation problem. A filter document with $or, $in and a regular expression is compact, but the SQL equivalent takes time to write. This tool reads the shell query and writes SQL for the dialect you pick: $and and $or groups, $in, comparison operators, $regex as LIKE or REGEXP, $exists, projection, sort, skip and limit, plus counting, distinct, inserts, updates with $set, $inc and $unset, deletes and simple pipelines with $match, $group, $lookup and $project. The query is parsed as text and never executed. Real collections are rarely shaped like tables, so treat the SQL as a draft. It runs in your browser.

How to use it

  1. Paste a MongoDB shell query, such as db.users.find({...}), into the input box.
  2. Choose the SQL dialect: PostgreSQL, MySQL or SQLite.
  3. Copy the SQL and adjust table and column names to your schema.

Frequently asked questions

Which operations can it translate?

find and findOne, countDocuments, distinct, insertOne and insertMany, updateOne and updateMany, deleteOne and deleteMany, and simple aggregate pipelines.

How are regular expressions translated?

Simple patterns become LIKE where possible, and other patterns use the dialect's regular expression operator, such as REGEXP in MySQL. Check complex patterns by hand.

Does it run the query?

No. The shell query is only parsed as text and never executed, and no database is contacted at any point, so you can paste queries from production logs without any side effects.

What happens to nested documents?

Dotted paths and embedded documents have no direct SQL equivalent, so you may need to map them to columns or JSON operators yourself.

Tools often used together

  • SQL to MongoDB QueryTranslate SQL into MongoDB shell syntax: SELECT -> find() with filter, projection, sort, skip, limit (or distinct); GROUP BY / aggregates / simple JOINs -> aggregate pipeline ($match, $lookup, $group, $project, $sort); INSERT VALUES -> insertOne/insertMany; UPDATE -> updateMany with $set/$inc; DELETE -> deleteMany. LIKE becomes a regex. Subqueries, UNION and CTEs are not supported.
  • MongoDB Aggregation Pipeline BuilderFill in $match, $unwind, $lookup, $group, $sort, $project, $skip, $limit and get a pipeline for mongosh, Node, PyMongo or plain JSON.
  • SQL Query Explainer (plain English)Explain a SELECT / INSERT / UPDATE / DELETE / CREATE TABLE statement in plain English: tables and joins, filters, grouping, ordering and limits in logical execution order, plus warnings about common pitfalls (SELECT *, leading-wildcard LIKE, functions on columns, big OFFSET, UPDATE/DELETE without WHERE). Rule-based parser: no CTEs, UNION or window frames.
  • JSON to SQL (CREATE TABLE + INSERT)Infer a table from a JSON array of objects: column types, NULLability, and escaped INSERT statements for PostgreSQL, MySQL or SQLite.
  • SQL DDL Converter (PostgreSQL / MySQL / SQLite)Convert CREATE TABLE / CREATE INDEX DDL between PostgreSQL, MySQL and SQLite: SERIAL <-> AUTO_INCREMENT, BOOLEAN <-> TINYINT(1), TIMESTAMPTZ <-> DATETIME, UUID <-> CHAR(36), JSONB <-> JSON, defaults (now(), true/false), identifier quoting, PK/UNIQUE/FK and indexes. DDL is parsed and re-emitted; views, triggers, functions, partitions and CHECK constraints are not carried over.
  • SQL FormatterUppercase keywords and lay out clauses, joins and subqueries on separate lines.
