YAML / JSON to Terraform HCL

Turns YAML or JSON in the Terraform JSON-syntax shape (resource, variable, output, locals, provider, terraform) into HCL, writing expressions unquoted, repeated blocks as nested blocks and aligning output like terraform fmt.

Use the tool

Why this tool exists

If a script or generator produces your infrastructure description as YAML or JSON, someone still has to turn it into HCL for people to read and review. Doing it by hand risks mistakes with quoting and block structure. Paste the data here and the tool writes HCL: a string that is a single "${...}" expression is written unquoted, lists of mappings become repeated nested blocks, known block names such as lifecycle and connection become blocks, and other mappings such as tags stay attribute maps. Output is aligned in the style of terraform fmt. The input must follow the Terraform JSON shape, with top-level keys like resource and variable. The conversion runs in your browser.

How to use it

  1. Paste YAML or JSON in the Terraform structure into the input box.
  2. Run the conversion to see the HCL.
  3. Copy it into a .tf file and run terraform fmt and terraform validate.

Frequently asked questions

What input shape does it expect?

The Terraform JSON syntax: top-level keys such as terraform, variable, resource, output, locals and provider, with resources nested by type and name.

How are "${...}" strings treated?

A string that is exactly one ${...} expression is written without quotes, so references like aws_instance.web[0].public_ip become real expressions in HCL.

How does it decide between blocks and maps?

Known block names such as lifecycle and connection, and lists of mappings, become blocks. Other mappings, like tags, stay as attribute maps with an equals sign.

Does the output need checking?

Yes. Run terraform fmt and terraform validate on the result, ideally in a scratch directory. Unusual structures or block names that the tool does not recognise may need a manual fix.
