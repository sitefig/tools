GitLab CI Linter: .gitlab-ci.yml Structure Check

Checks the structure of a .gitlab-ci.yml: YAML syntax, jobs, stages, needs, extends, when values and keywords outside the documented list.

Use the tool

Why this tool exists

GitLab's own CI lint needs a project and a login. This page gives a quick structural check you can run on any file, for example while reviewing a merge request.

It flags clear mistakes as problems and doubtful ones as review items. It cannot see include files, variables, rules logic or runner settings, so a pass here is not a pass in GitLab. Keyword names come from the GitLab CI/CD YAML reference.

How to use it

  1. Paste your .gitlab-ci.yml.
  2. Read the Problems list first, then the Review list.
  3. Fix the file and paste again.
  4. Run GitLab's own CI lint for the final check.

Frequently asked questions

Does it replace GitLab's CI lint?

No. It checks structure only. It does not fetch includes, expand variables or evaluate rules.

Why is a keyword marked for review?

It is not in the documented job keyword list. It may be a typo, or a newer keyword than this list.

Are only and except an error?

No. They are reported for review because GitLab recommends rules for new pipelines.

Is the file sent anywhere?

No. Parsing happens in your browser.
