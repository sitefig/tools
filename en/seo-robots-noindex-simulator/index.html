Robots / Noindex Indexability Simulator

Paste a robots.txt and a page's response headers with its HTML head to see whether a URL can be crawled and indexed, and get a warning about blocking a noindex page in robots.txt.

Use the tool

Why this tool exists

Crawling and indexing are two separate steps, and the controls interact in ways that surprise people. A page blocked in robots.txt cannot be fetched, so a noindex tag on it is never seen, and the URL can still appear in results without a snippet. A canonical tag may point somewhere else entirely. Each signal alone looks fine.

This simulator reads all of them together for a user agent and a path you choose. It reports whether the path is allowed to be crawled, which directives apply and whether the page can be indexed. It explains the common mistake that keeps pages in the index. It uses the text you paste and does not fetch your site, and it follows common rules, so confirm important cases in Search Console.

How to use it

  1. Paste your robots.txt into the first box.
  2. Paste the response headers, a blank line, then the page HTML head into the second box.
  3. Enter the URL path to test and the user agent, such as Googlebot.
  4. Read the crawl and index verdict and any warnings about conflicting signals.

Frequently asked questions

Why can a blocked page still appear in search?

If other pages link to it, a search engine can list the URL without having crawled it. To keep a page out, allow crawling and use noindex, otherwise the tag is never seen.

Which wins, X-Robots-Tag or meta robots?

Both are read, and the most restrictive directive generally applies. A noindex in either place is enough to keep the page out of the index when it can be crawled.

Does the tool fetch my live site?

No. It only analyses the text you paste, so the answer matches your input, not necessarily what the live server sends. Compare it with a real fetch, for example in a URL inspection tool.
