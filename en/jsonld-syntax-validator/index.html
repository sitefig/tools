JSON-LD Syntax Validator

Parses JSON-LD with its own strict parser, reports the exact line and column of any error, and then checks @context, @type and @id. Paste raw JSON or a whole page and it finds the ld+json scripts.

Use the tool

Why this tool exists

Most broken structured data is a typo in the JSON: a trailing comma, smart quotes copied from a document, or a missing bracket. Browsers and search engines then ignore the whole block without saying why. This tool points at the exact spot and explains the problem in plain words.

After the syntax passes it checks the parts that make JSON-LD work: a schema.org @context, an @type that exists in the current vocabulary (with a did-you-mean for typos such as Organisation), and well-formed @id and @graph values. It does not check properties or Google requirements; use the property checker and the eligibility checker for that.

How to use it

  1. Paste the JSON-LD, or the whole HTML page with its script tags.
  2. Read the first error with its line and column and fix it.
  3. Run again until the output says Valid JSON.
  4. Review the @context and @type findings, then copy the reformatted JSON.

Frequently asked questions

Does it find several errors at once?

It reports the first syntax error, as JSON parsers do, because everything after it is unreliable. Semantic findings (context, type, id) are listed together once the syntax is valid.

Which Schema.org version is used?

Version 29.2 of the vocabulary. The page says so in the output. New types added later will show as unknown until the tool is updated.

Why does it flag duplicate keys?

JSON allows them but keeps only the last value, so the first one is silently lost. That is nearly always a mistake.

Is my markup sent anywhere?

No. Parsing and checking happen in your browser.
