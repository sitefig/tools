Text Chunk Splitter (RAG)

Paste text and split it into overlapping chunks of a chosen size, measured in characters or approximate tokens, breaking at paragraphs or sentences where possible.

Use the tool

Why this tool exists

Retrieval pipelines cut documents into chunks before embedding them. Too large and each vector blurs several topics; too small and meaning is lost. Overlap repeats a little text across boundaries so that a sentence split in two can still be found.

This splitter lets you try sizes on real text before writing code. It cuts at the last paragraph, sentence or line break in the second half of each window when that option is on, and falls back to a hard cut otherwise. Each chunk is labelled with its length and an approximate token count. Token sizes use a four-characters-per-token rule, so they are rough guides only.

How to use it

  1. Paste the text you want to split into the input.
  2. Set the chunk size and overlap, and choose characters or approximate tokens.
  3. Leave boundary preference on, then copy the numbered chunks from the output.

Frequently asked questions

How is the token unit measured?

The approximate token option multiplies your size and overlap by four to get characters. It is a rough rule for English text, not a tokenizer.

What does boundary preference do?

It looks in the second half of each window for the last blank line, sentence end or line break and cuts there, so chunks tend to end on natural breaks.

Why must overlap be smaller than the size?

Otherwise each chunk would start where the previous one began and the splitter would never advance. The tool reports an error in that case.

Can I see the chunks coloured?

Not in this tool, which prints numbered chunks as text. Use the RAG Chunking Visualizer to see colour-coded chunks with the overlapping parts highlighted.
