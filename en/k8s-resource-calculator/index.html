Kubernetes Resource & Node Sizing Calculator

Calculates total CPU and memory requests and limits for a Deployment, its QoS class, the overcommit ratio, and how many worker nodes you need given node size, system reserve, DaemonSet overhead and max pods.

Use the tool

Why this tool exists

Sizing a Kubernetes workload usually starts with a guess: three replicas, 250m CPU, 256Mi memory. The questions that follow are practical. What do all replicas request in total, including the autoscaler's maximum? Will it be Guaranteed, Burstable or BestEffort? How overcommitted are the limits? And how many nodes of a given size are needed once you subtract the system reserve and DaemonSets? This calculator answers those with the Kubernetes quantity syntax you already use (500m, 0.5, 256Mi, 1Gi). It is a planning aid based on the numbers you enter, not measured usage, so verify with real metrics. It runs in your browser, with nothing to install.

How to use it

  1. Enter replicas, the HPA maximum and the CPU and memory requests and limits per pod.
  2. Enter the node CPU and memory, the system reserve, DaemonSet overhead and max pods per node.
  3. Read the totals, QoS class, overcommit ratios and the number of nodes needed.

Frequently asked questions

What quantity formats are accepted?

Kubernetes style values: millicores such as 500m or decimal CPUs such as 0.5, and memory with suffixes such as 256Mi and 1Gi.

How is the QoS class decided?

Guaranteed when requests equal limits for CPU and memory, BestEffort when none are set, and Burstable in all other cases.

How are node counts calculated?

The tool subtracts the system reserve and DaemonSet use from each node, then divides pod requests by what is left, also respecting the max-pods limit. The larger result wins.

Is this a prediction of real usage?

No. It only does arithmetic on the values you give it. Use monitoring data to choose requests and limits, then use the calculator to plan capacity.
