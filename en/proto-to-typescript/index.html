Protobuf to TypeScript Interfaces

Converts .proto messages and enums into TypeScript interfaces and types that match the proto3 JSON mapping: nested messages as Outer_Inner, repeated as arrays, map as Record. Services are ignored.

Use the tool

Why this tool exists

A browser client that talks to a gRPC-Web gateway or a JSON transcoding proxy receives plain JSON, not binary protobuf. It still helps to have types for those payloads. Full generators such as protoc plugins are the right tool for production, but they need setup, and sometimes you only want the data shapes for a quick script or review. Paste the messages here and get interfaces following the JSON mapping: camelCase fields, int64 as string or number as you choose, Timestamp as a string, oneof members optional and enums as string unions or TypeScript enums. Services and RPC definitions are ignored. The conversion runs in your browser.

How to use it

  1. Paste the .proto source into the input box.
  2. Choose camelCase names, how 64-bit integers are typed, and whether to emit TypeScript enums.
  3. Copy the interfaces into your project.

Frequently asked questions

How are nested messages named?

A message Inner declared inside Outer becomes the interface Outer_Inner. That avoids name clashes between nested messages with the same name and keeps their origin visible in the output.

How are repeated and map fields typed?

Repeated fields become arrays of the element type, and map fields become Record types that carry the key and value types, which matches how the JSON mapping represents them.

What happens to oneof?

Each member of a oneof becomes an optional property, because in a real message at most one of them is present. Your code can check which one is set before using it.

Does it generate gRPC client code?

No. Services and RPC methods are ignored. It only produces data types, so use protoc or ts-proto for client code.

Tools often used together

  • Protobuf Message to Sample JSONParse a .proto (proto2/proto3) file and generate a sample JSON document for a message following the canonical proto3 JSON mapping: lowerCamelCase names, int64 as strings, bytes as base64, enums by name, maps as objects, Timestamp as RFC 3339, oneof (first member only).
  • Protobuf to JSON SchemaConvert .proto messages and enums to a JSON Schema draft-07 document with definitions, following the proto3 JSON mapping (int64 as numeric strings, bytes as base64, Timestamp as date-time).
  • Protobuf FormatterFormat .proto files: one statement per line, consistent indentation and spacing; comments are kept.
  • JSON Schema to ProtobufConvert a JSON Schema (draft-07 / 2020-12 subset with properties, $ref/definitions, enums, arrays, additionalProperties) into proto3 messages: nested objects become messages, arrays become repeated, string enums get an UNSPECIFIED zero value, date-time maps to google.protobuf.Timestamp, non-required fields are optional. oneOf/anyOf with several non-null branches fall back to google.protobuf.Value.
  • GraphQL Schema to TypeScriptConvert GraphQL SDL (type, input, interface, enum, union, scalar, descriptions) into TypeScript interfaces and types. Interface fields are inlined into implementing types; nullable output fields become "T | null", nullable input fields become optional. Query/Mutation root types are skipped unless enabled; field arguments are ignored.
  • TypeScript Interface to JSON SchemaConvert TypeScript interfaces, type aliases and enums to JSON Schema draft-07 (definitions + $ref). Supports optional props, unions, literals, tuples, arrays, Record, Date, index signatures, extends/intersections and JSDoc descriptions. Not supported: conditional/mapped types, keyof/typeof and most utility generics.
