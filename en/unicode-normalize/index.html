Unicode Normalizer

Rewrites text into a chosen Unicode normalisation form, with optional accent stripping and removal of zero-width characters and soft hyphens. It also reports how many code points went in and came out.

Use the tool

Why this tool exists

Two strings can look identical on screen and still fail an equality check. The letter e with an acute accent can be one code point or an e followed by a combining mark, and a search, a database lookup or a filename comparison will treat them as different. Compatibility characters like the fi ligature, circled digits and full-width letters add to the confusion.

This tool lets you see and fix that. Pick a normalisation form, optionally strip diacritics for slugs or loose matching, and remove invisible characters that sneak in from copied web text. The code point count before and after shows whether anything actually changed. It all runs locally, so internal data stays on your machine.

How to use it

  1. Paste your text into the input box.
  2. Choose a form: NFC, NFD, NFKC or NFKD.
  3. Tick Strip diacritics to drop accents, and Remove zero-width / soft hyphen if needed.
  4. Read the output and the code point counts underneath, then copy the result.

Frequently asked questions

Which form should I use?

NFC is the usual choice for storing and comparing text. NFD splits letters from their accents. NFKC and NFKD also fold compatibility characters, so ligatures and full-width letters become plain ones, which suits search but loses some formatting.

What exactly does strip diacritics remove?

It decomposes the text, deletes all combining marks, then recomposes using the form you selected. Cafe with an accent becomes plain Cafe. It does not transliterate letters such as the Danish o with a stroke, which has no combining mark.

Which invisible characters are removed?

The zero-width space, zero-width non-joiner and joiner, word joiner, byte order mark and soft hyphen. Other invisible characters, such as directional marks, are left in place.

Why do the code point counts differ?

Normalisation can merge a base letter and its combining mark into one code point, or split them apart. The counts under the output show that change, and they also reflect characters that were removed.
