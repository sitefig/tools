JSON Schema to Protobuf

Converts a JSON Schema into proto3 messages: nested objects become messages, arrays become repeated fields, string enums gain an UNSPECIFIED zero value and date-time becomes Timestamp.

Use the tool

Why this tool exists

When a JSON API grows into gRPC, or a service must share a data contract with a protobuf system, someone has to rewrite the schema as .proto. The two models differ in ways that cause mistakes: protobuf enums need a zero value, every field needs a stable number, and there is no direct form of optional or free-form object. This tool takes a JSON Schema using properties, $ref and definitions, enums, arrays and additionalProperties, and writes proto3 messages from it. Maps come from additionalProperties, required fields are plain and others are optional. Where a oneOf or anyOf has several real branches, it falls back to google.protobuf.Value. Field numbers are assigned in order, so lock them in before shipping. It runs in your browser.

How to use it

  1. Paste a JSON Schema (draft-07 or 2020-12 subset) into the input box.
  2. Enter an optional package name such as example.v1.
  3. Copy the proto3 output, review the field numbers and names, and commit it only once they are final.

Frequently asked questions

How are enums converted?

String enums become a proto enum with an UNSPECIFIED value at zero, since proto3 requires a zero value, followed by the original values.

What happens to oneOf and anyOf?

If there is a single non-null branch, it is used. With several real branches, the field falls back to google.protobuf.Value, because protobuf has no direct equivalent.

Are field numbers stable?

They are assigned in the order properties appear. Once clients use the schema, do not renumber, and keep the numbers if you add fields later.

Which formats are mapped?

date-time becomes google.protobuf.Timestamp. Integers, numbers, booleans, strings and arrays map to their obvious proto types. Required properties are plain fields and the rest are optional.

Tools often used together

  • Protobuf FormatterFormat .proto files: one statement per line, consistent indentation and spacing; comments are kept.
  • Protobuf to JSON SchemaConvert .proto messages and enums to a JSON Schema draft-07 document with definitions, following the proto3 JSON mapping (int64 as numeric strings, bytes as base64, Timestamp as date-time).
  • Protobuf to TypeScript InterfacesConvert .proto messages and enums to TypeScript interfaces/types matching the proto3 JSON mapping (nested messages become Outer_Inner, repeated -> arrays, map -> Record, oneof members optional, int64 as string or number, Timestamp as string). Services are ignored.
  • JSON Schema GeneratorInfer a draft-07 JSON Schema from a sample document, with optional string format detection.
  • JSON Schema ValidatorValidate JSON data against a schema (type, properties, required, items, enum, min/max, pattern, anyOf/oneOf/allOf, local $ref).
  • TypeScript Interface to JSON SchemaConvert TypeScript interfaces, type aliases and enums to JSON Schema draft-07 (definitions + $ref). Supports optional props, unions, literals, tuples, arrays, Record, Date, index signatures, extends/intersections and JSDoc descriptions. Not supported: conditional/mapped types, keyof/typeof and most utility generics.
