auth.log and fail2ban Analyzer: Failed SSH Logins, Bans, sudo

Counts failed and accepted SSH logins, fail2ban bans and sudo commands from pasted logs.

Use the tool

Why this tool exists

After a server is online for a day the auth log fills with failed logins. A summary shows the busiest IPs, the user names tried and whether any login succeeded from an unexpected address.

Patterns follow OpenSSH, sudo and fail2ban wording. Wording varies a little by version and distribution, so some lines may be ignored.

How to use it

  1. Paste /var/log/auth.log (or secure) and fail2ban.log.
  2. Set how many rows to show.
  3. Read failed logins by IP and user.
  4. Check accepted logins and sudo commands.

Frequently asked questions

Does it ban IPs?

No. It only reads text.

Why are bans missing?

Include fail2ban.log. Bans are logged there, not in auth.log.

Are the results complete?

Only lines matching known patterns are counted.

Is my log uploaded?

No. Everything is processed in your browser and nothing is sent. Logs can hold IP addresses and tokens, so the page does not write them into the address bar.
