System Prompt Length Budgeter

Paste a system prompt with section headings and see roughly how many tokens each section uses and how much of the context window is left.

Use the tool

Why this tool exists

System prompts grow by accretion: a rule here, an example there, until a third of the budget is gone before the user says anything. It is hard to see which section is responsible when the whole thing is one block of text.

This tool splits the prompt at markdown headings or XML-style tags, estimates tokens for each part and shows each share of the total. It also subtracts your reserved output and history from the context window, so you can see what remains for documents and tool results. The counts are estimates from a heuristic, not the provider tokenizer, so leave a safety margin.

How to use it

  1. Paste your prompt, using ## headings or XML-style tags to mark sections.
  2. Set the context window, the output reserve, the history reserve and a model family.
  3. Read the table of sections and the remaining budget, then trim the largest parts.

Frequently asked questions

How are sections detected?

Any markdown heading line, or a line that is only an opening XML-style tag, starts a new section. Text before the first one is shown as preamble.

How accurate are the token counts?

They are approximate, based on word pieces of about four characters, with a small adjustment per model family. Expect an error of roughly ten to twenty percent; real tokenizers differ.

What does Over Budget mean?

The prompt plus the output and history reserves exceed the context window you entered, so there is no room left for documents or tool output.

Does it send my prompt anywhere?

No. The prompt is analysed in your browser. No model is called, no tokenizer vocabulary is downloaded, and nothing you paste is stored or uploaded anywhere.

Tools often used together

  • LLM Token Count Estimator (approximate)ESTIMATE of token counts for GPT-4o, GPT-4, Claude, DeepSeek and Llama from text, using per-model chars-per-token ratios and a word/punctuation heuristic. No vocabulary is available offline, so counts are approximate (typically within 10-20% for English).
  • GPT Token Counter (cl100k + o200k, chat overhead)Exact token counts for text under cl100k_base and o200k_base side by side, plus an approximate chat-message overhead calculator (OpenAI cookbook rule: 3 tokens per message, +1 per name, +3 reply priming; use o200k_base for the GPT-4o family). Only OpenAI encodings (cl100k_base, o200k_base) are included. Claude, DeepSeek and Gemini tokenizers are NOT included (their vocabularies are not available offline): use the llm-token-estimator tool for approximate counts of those.
  • Prompt Template Variable FillerFill {{variables}} in a prompt template from KEY=VALUE lines or JSON; reports missing and unused variables.
  • LLM Context Window ShrinkerShrink text to fit a token budget: keep head, tail, both ends, drop duplicate lines, or keep the most informative sentences in original order (frequency-based extractive summary). Token counts are estimates (characters / ratio), not a real tokenizer.
  • Prompt Linter / Optimizer ChecklistRule-based review of an LLM prompt (no model is called): checks for role, task, output format, constraints, examples, structure, vague or hedging wording, shouting, negative-only instructions, unfilled placeholders, repeated sentences and length, then lists concrete fixes with a score.
  • System Prompt XML BuilderTurn a plain outline of prompt sections into a well-structured, XML-tagged system prompt (the structure recommended for Claude and also effective for other models): role, context, instructions, constraints, examples (grouped in <examples>), output format and a document/input placeholder, with consistent tag names, escaped content where needed and an approximate token count.
