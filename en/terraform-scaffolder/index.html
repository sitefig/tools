Terraform AWS Scaffolder

Choose a region, a name prefix and the pieces you want, and get a formatted Terraform starting point with provider, state backend, VPC, S3 bucket and EC2.

Use the tool

Why this tool exists

Every new AWS project begins with the same boilerplate: required_providers, a backend, a VPC with public subnets and route tables, a bucket with encryption and public access blocked. Writing it from memory is slow, and copying from an old repo carries over stale settings.

This scaffolder produces that skeleton with sensible defaults, such as versioning, AES256 encryption, a blocked public bucket policy and IMDSv2 required on the instance. The output is a starting point, not a reviewed production design. Check the CIDR ranges, security group rules and instance size before you apply anything. All generation happens in your browser.

How to use it

  1. Set the AWS region and a lowercase name prefix.
  2. Pick the state backend and tick the VPC, S3 bucket or EC2 blocks you need.
  3. Copy the generated code into main.tf and review it before running terraform plan.

Frequently asked questions

Is the code ready for production?

No. It is a scaffold with safe-looking defaults. The EC2 security group opens port 443 to the whole internet, for example. Review every block, then run terraform plan.

What does the S3 backend option do?

It adds a backend block pointing at a bucket named from your prefix, with encryption and a lockfile. You must create that bucket yourself first; the tool does not create it.

Which provider version is used?

It pins the AWS provider to the 5.x series with a pessimistic constraint. Change the version if your project needs a different major release.

Are credentials involved?

No. Nothing is read from AWS and no keys are needed. The tool only generates text from the values you type.
