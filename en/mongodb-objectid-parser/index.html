MongoDB ObjectId Parser

Paste one or more 24-character ObjectIds and read the creation timestamp, the random part and the counter inside each of them.

Use the tool

Why this tool exists

The first four bytes of a MongoDB ObjectId are a Unix timestamp in seconds, which means that you can often tell when a document was created without a createdAt field. That is handy when you are debugging an incident, auditing old records or checking whether two ids came from the same period.

This tool splits each id into its parts: the time as an ISO date, the five-byte random value and the three-byte counter. It runs locally and accepts many ids at once. The embedded time is the moment the id was generated, usually by the driver, which may differ from when the document was inserted. Anyone can also make an id with any time.

How to use it

  1. Paste ObjectIds into the input, one per line.
  2. Read the decoded creation time, random value and counter under each id.
  3. Copy the dates you need into your notes or ticket.

Frequently asked questions

What format must the id have?

It must be exactly 24 hexadecimal characters, such as 507f1f77bcf86cd799439011. Anything else stops the tool with an error that shows the value that failed.

Is the timestamp the insert time?

It is when the id was generated, usually in the client driver. The document may be inserted later, and anyone can build an id with a chosen time, so do not use it as proof.

What are the random value and counter?

The random value is five bytes chosen per process and the counter is a three-byte number that increases for each id generated. Together they make ids unique within a second.

Does it connect to a database?

No. It only decodes the hexadecimal text you paste, inside your browser, and never contacts a database or any server with your data.
