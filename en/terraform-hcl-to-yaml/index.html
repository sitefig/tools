Terraform HCL to YAML

Parses Terraform or HCL2 configuration and prints it as YAML using the Terraform JSON structure: labelled blocks nested, unlabelled blocks as lists and expressions as "${...}" strings.

Use the tool

Why this tool exists

YAML is easier on the eyes than JSON and fits tools that already read YAML, such as config pipelines, Kubernetes-style tooling and documentation. If you want to inspect or transform Terraform with those tools, you need the HCL in YAML form. Paste your configuration here and you get the same structure Terraform uses for its JSON syntax, written as YAML: resource, type and name nested as maps, repeated blocks as lists and non-literal expressions kept as quoted "${...}" strings. Nothing is evaluated, and dynamic blocks are not expanded. The reverse direction is available in the YAML / JSON to Terraform HCL tool. Parsing is local to your browser.

How to use it

  1. Paste your Terraform or HCL configuration into the input box.
  2. Run the conversion to see the YAML.
  3. Copy it into your pipeline, or use the reverse tool to turn it back into HCL.

Frequently asked questions

Is the structure the same as the JSON version?

Yes. It uses the Terraform JSON syntax shape and prints it as YAML. The JSON converter on this site gives the same data as JSON.

Why do some values look like "${var.name}"?

Expressions are kept as strings in Terraform's JSON syntax. They are not evaluated, so references and function calls appear as quoted text.

Does it support every HCL feature?

It parses common HCL2 syntax, including comments and heredocs. Dynamic blocks are not expanded and no expression is evaluated, so variables and functions appear as text rather than computed values.

Is my Terraform code uploaded?

No. The conversion runs entirely in your browser, and the text of your configuration is not sent to any server, so internal resource names and settings stay on your own machine.

Tools often used together

  • Terraform HCL to JSONParse Terraform / HCL2 configuration into JSON. Labeled blocks nest by label (resource.aws_instance.web), unlabeled blocks become arrays, non-literal expressions (references, function calls, conditionals, for expressions) are kept as "${...}" strings as in the Terraform JSON syntax. Comments and heredocs are handled; dynamic blocks are not expanded.
  • YAML / JSON to Terraform HCLTurn YAML or JSON in Terraform JSON-syntax shape (resource: {type: {name: {...}}}, variable:, output:, locals:, provider:, terraform:) into HCL. Strings that are a single "${...}" expression are written unquoted, lists of mappings become repeated nested blocks, known block names (lifecycle, connection, ...) become blocks, other mappings (tags, etc.) stay attribute maps. Output is aligned like terraform fmt.
  • Terraform / HCL FormatterIndent HCL by nesting depth and align "=" in consecutive attribute lines (terraform fmt style). Heredocs untouched.
  • YAML FormatterRe-indent and normalise YAML (comments are not preserved; anchors are expanded).
  • JSON to YAMLConvert JSON to clean block-style YAML.
  • Terraform AWS ScaffolderScaffold providers, remote state, VPC, S3 bucket and EC2 instance blocks (formatted like terraform fmt).
