SQL INSERT to JSON

Paste a SQL script with INSERT statements and get JSON rows grouped by table, with strings, numbers, NULL and booleans converted to JSON values.

Use the tool

Why this tool exists

A database dump or a seed script holds data in INSERT statements, but a front-end mock, a test fixture or a document store needs JSON. Loading the dump into a database just to export it again is heavy for a handful of rows.

This parser reads INSERT ... VALUES, including multi-row statements, quoted strings with doubled quotes, NULL, true and false and numbers. Column names come from the INSERT column list, or from a CREATE TABLE in the same script when the INSERT has none. It handles a subset only: INSERT and CREATE TABLE. Expressions such as function calls stay as raw text, and SELECT-based inserts, updates and other statements are ignored. Check results against your source data.

How to use it

  1. Paste the SQL script with CREATE TABLE and INSERT statements.
  2. Choose one object per table or a flat array of rows, and the indent.
  3. Copy the JSON output.

Frequently asked questions

Where do the column names come from?

From the column list in the INSERT, if present, otherwise from a CREATE TABLE for the same table in your script. Without either, columns are named col1, col2 and so on.

What SQL does it support?

INSERT ... VALUES, optionally multi-row, and CREATE TABLE for column names. Statements like UPDATE, DELETE and INSERT ... SELECT are skipped, and function calls in values are kept as raw text.

How are types converted?

Numbers become JSON numbers, NULL becomes null, TRUE and FALSE become booleans and quoted strings become strings with doubled quotes resolved. Dates stay as strings.

What if the column count does not match?

The tool stops with an error saying how many values and columns the row has, so you can find the broken statement.

  • SQL on CSV / JSON (in-browser SQL)Run SQL against pasted CSV or JSON. Box 1: tables separated by a line of ---, each CSV (first row = header) or a JSON array of objects, optionally starting with "-- name: users"; they become t1, t2, ... (and the name). You can also put CREATE TABLE / INSERT statements in either box. Box 2: statements separated by ;. Supported: SELECT with expressions, aliases, DISTINCT, WHERE (AND OR NOT, comparisons, LIKE, GLOB, IN, BETWEEN, IS [NOT] NULL, EXISTS), INNER/LEFT/RIGHT/FULL/CROSS JOIN with ON or USING, GROUP BY/HAVING, COUNT SUM AVG MIN MAX TOTAL GROUP_CONCAT (DISTINCT ok), ORDER BY (aliases, ordinals, NULLS FIRST/LAST), LIMIT/OFFSET, subqueries (FROM, IN, EXISTS, scalar, correlated), WITH (non-recursive), UNION [ALL]/INTERSECT/EXCEPT, CASE, CAST, string and math functions, CREATE TABLE [AS], CREATE VIEW, INSERT, UPDATE, DELETE, DROP. Differences from SQLite: "/" is always true division, numeric-looking text compares as a number, empty CSV cells are NULL, no constraint enforcement (PRIMARY KEY/UNIQUE/NOT NULL), no window functions, recursive CTEs, triggers or date functions. Output is a text table plus CSV; nothing leaves your browser.
