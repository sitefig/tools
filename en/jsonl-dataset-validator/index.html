JSONL Dataset Validator

Paste a JSONL file and see which lines are invalid JSON, have bad chat roles, lack an assistant reply or miss prompt and completion fields.

Use the tool

Why this tool exists

Fine-tuning jobs fail late and with short messages, often because one line of a large file has a trailing comma, an unknown role or an empty message. Finding line 4,381 by eye is no fun.

This validator reads the file line by line and reports each problem with its line number. For chat data it checks that messages is a non-empty array, roles are known, content is present and non-empty, and at least one assistant turn exists to learn from. It can also check prompt and completion pairs, or just any object. It adds a rough token estimate of the content. Provider rules differ, so check your provider guide as well.

How to use it

  1. Paste your JSONL, one JSON object per line.
  2. Choose the expected format: chat messages, prompt and completion, or any object.
  3. Read the summary and the list of problems, fix those lines, and run it again.

Frequently asked questions

Which roles are accepted?

system, user, assistant, tool and developer. Any other role is flagged. If your provider accepts a different set, treat this check as a hint only.

Does it check provider limits?

No. It does not check maximum tokens per example, file size or the number of examples. It gives an approximate token total to help you plan.

How are blank lines treated?

Empty lines are skipped. A line that has content but is not valid JSON is reported with the parser error message.

Is my dataset uploaded?

No. Validation runs in your browser. Very large files can still be slow to paste, so test a sample first.
