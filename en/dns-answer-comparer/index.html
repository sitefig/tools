DNS Answer Comparer: Compare Two Resolver Results After a Change

Compares two sets of DNS records and shows what is the same, what is only in one answer and where the TTL differs. Useful after a DNS change or migration.

Use the tool

Why this tool exists

After a DNS change, different resolvers answer differently until caches expire. Running dig against two resolvers and comparing by eye is slow and error-prone, especially with several records.

This page does not look anything up. Run dig yourself, for example dig @8.8.8.8 example.com A and dig @1.1.1.1 example.com A, and paste both. Records are compared as sets, ignoring order and a trailing dot. Round-robin or geo DNS can differ legitimately.

How to use it

  1. Run dig against resolver A and paste the answer in the first box.
  2. Do the same for resolver B.
  3. Read the verdict and the lists.
  4. Wait for the TTL to pass and compare again.

Frequently asked questions

Which input formats work?

Full dig answer lines (name TTL IN TYPE value), lines without TTL, and bare TYPE value lines.

Why do TTLs differ?

A resolver that cached the record earlier shows the remaining time, so the numbers count down.

Does it query DNS?

No. A web page cannot send DNS queries. You paste results you got elsewhere.

What does a difference mean?

Usually propagation in progress. It can also be load-balanced or geo-aware DNS.
