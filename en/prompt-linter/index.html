Prompt Linter / Optimizer Checklist

Reviews an LLM prompt with a fixed checklist: role, task, output format, examples, vague or hedging words, shouting, placeholders, repeated sentences and length. It lists concrete fixes and a score.

Use the tool

Why this tool exists

Most weak prompts fail for boring reasons: no clear task, no output format, vague words like "good" or "some", a placeholder left unfilled, or three warnings in capital letters. A checklist catches these quickly, before you spend tokens testing. This linter applies a set of simple rules to your text and reports what is missing, what is vague and what is repeated, with a suggested fix for each issue and an overall score. No model is called, so it is instant and free, and your prompt, which may contain business details, stays in your browser. Treat the result as a first review, not a verdict. Only testing on real inputs shows whether a prompt works.

How to use it

  1. Paste your prompt into the input box.
  2. Run the check and read the score, then the list of issues with suggested fixes.
  3. Edit the prompt, paste it in again, and test the final version on real inputs.

Frequently asked questions

Does this use an AI model to judge the prompt?

No. It uses plain pattern rules on the text, so the result is the same every time and nothing is sent anywhere. It cannot judge whether the prompt actually produces good answers.

What does the score mean?

It is the weighted share of checks passed. Task, output format, vague wording and unfilled placeholders count double. A high score means fewer common mistakes, not a guaranteed good prompt.

Why is "never" or "do not" flagged?

When prohibitions outnumber positive instructions, the tool suggests saying what to do instead of only what to avoid. A couple of prohibitions are fine.

Which placeholders does it detect?

Forms like {{name}}, {name}, [INSERT ...] and [TODO ...] in square brackets. They are flagged because an unfilled one would reach the model as literal text.

Tools often used together

  • System Prompt FormatterRestructure a free-form system prompt into labelled sections (role, context, instructions, constraints, output format, examples) using XML tags or Markdown headings. Sections are detected from existing headings/tags or, failing that, by keyword heuristics per paragraph or bullet; review the result, it does not rewrite wording.
  • System Prompt XML BuilderTurn a plain outline of prompt sections into a well-structured, XML-tagged system prompt (the structure recommended for Claude and also effective for other models): role, context, instructions, constraints, examples (grouped in <examples>), output format and a document/input placeholder, with consistent tag names, escaped content where needed and an approximate token count.
  • Few-Shot Prompt FormatterFormat input => output example pairs as a few-shot prompt: plain labels, XML tags, Markdown, or ready-to-send OpenAI / Anthropic message JSON. Use \n inside an example for line breaks.
  • Prompt Template Variable FillerFill {{variables}} in a prompt template from KEY=VALUE lines or JSON; reports missing and unused variables.
  • LLM Token Count Estimator (approximate)ESTIMATE of token counts for GPT-4o, GPT-4, Claude, DeepSeek and Llama from text, using per-model chars-per-token ratios and a word/punctuation heuristic. No vocabulary is available offline, so counts are approximate (typically within 10-20% for English).
  • Chain-of-Thought Prompt BuilderWrap a task in a reasoning prompt pattern: zero-shot CoT, structured steps, plan-and-solve, self-consistency, step-back, tree-of-thought panel or scratchpad tags, with a choice of answer format.
