Protobuf Formatter

Format a .proto file so each statement sits on its own line with consistent indentation and spacing. Messages, enums, oneofs and services are indented, and comments are kept.

Use the tool

Why this tool exists

Protocol Buffers definitions are shared between teams and generated into several languages, so a messy .proto file spreads confusion widely. Files copied from documentation or squeezed onto a few lines are hard to read, and field numbers are easy to misread.

The formatter puts each field, option and rpc on its own line, indents nested messages, enums, oneofs and service blocks, and sets spacing around equals signs and inside field options such as [deprecated = true]. Comments, including trailing ones, are kept. It formats layout only: it does not check field numbers for clashes or compile the file, so run protoc or buf for that. Your definitions stay in the browser and are not uploaded.

How to use it

  1. Paste your .proto content into the input box.
  2. Choose an indent of 2 spaces, 4 spaces or a tab.
  3. Check the formatted messages, enums and services.
  4. Copy the result into your repository and compile it with protoc or buf.

Frequently asked questions

Does it check field numbers?

No. It does not compile the schema, so duplicate or reserved field numbers are not detected. Use protoc or buf lint for real validation.

Are comments preserved?

Yes, both line comments on their own lines and trailing comments after a field. Their text is not changed.

Does it support proto2 and proto3?

It formats layout, which is largely the same in both. Syntax statements, messages, enums, oneof, map fields, services and options are handled.

Will it change the wire format?

No. Only whitespace and line breaks change. Field names, numbers and types stay exactly as in your input.

Tools often used together

  • Protobuf Message to Sample JSONParse a .proto (proto2/proto3) file and generate a sample JSON document for a message following the canonical proto3 JSON mapping: lowerCamelCase names, int64 as strings, bytes as base64, enums by name, maps as objects, Timestamp as RFC 3339, oneof (first member only).
  • Protobuf to TypeScript InterfacesConvert .proto messages and enums to TypeScript interfaces/types matching the proto3 JSON mapping (nested messages become Outer_Inner, repeated -> arrays, map -> Record, oneof members optional, int64 as string or number, Timestamp as string). Services are ignored.
  • Protobuf to JSON SchemaConvert .proto messages and enums to a JSON Schema draft-07 document with definitions, following the proto3 JSON mapping (int64 as numeric strings, bytes as base64, Timestamp as date-time).
  • JSON Schema to ProtobufConvert a JSON Schema (draft-07 / 2020-12 subset with properties, $ref/definitions, enums, arrays, additionalProperties) into proto3 messages: nested objects become messages, arrays become repeated, string enums get an UNSPECIFIED zero value, date-time maps to google.protobuf.Timestamp, non-required fields are optional. oneOf/anyOf with several non-null branches fall back to google.protobuf.Value.
  • JSON FormatterPretty-print JSON with custom indent and optional key sorting; errors show line and column.
  • YAML FormatterRe-indent and normalise YAML (comments are not preserved; anchors are expanded).
