ULID Decoder (Timestamp and Random Part)

Reads the creation time and the random part out of ULIDs, one per line.

Use the tool

Why this tool exists

A ULID packs a 48-bit millisecond Unix timestamp and 80 random bits into 26 characters of Crockford Base32. That is why ULIDs sort by creation time, and why you can read when a record was made from its ID alone.

Paste ULIDs from a database or a log and see the time in ISO format. The decoder accepts lower case and the usual look-alike letters (I and L read as 1, O as 0). It rejects values whose first character is above 7, because the time field is only 48 bits. It was checked against the example in the ULID specification and against an independent Python decode.

How to use it

  1. Paste one or more ULIDs, one per line.
  2. Read the ISO time and the Unix milliseconds.
  3. Check the random part if you need to compare IDs.
  4. Fix any line that shows an error message.

Frequently asked questions

How precise is the time?

To the millisecond. IDs made in the same millisecond differ only in their random part.

Why is a ULID rejected?

It must be 26 Crockford Base32 characters and the first one must be 0 to 7. Letters I, L, O and U are not in the alphabet, though I, L and O are read as look-alikes.

Does it verify that the ID was really created then?

No. The time is whatever the generator wrote. Anyone can make a ULID with any time.

Can it create ULIDs?

Use the ULID generator tool for that.
