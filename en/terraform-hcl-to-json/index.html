Terraform HCL to JSON

Parses Terraform or HCL2 configuration into JSON. Labelled blocks nest by label, unlabelled blocks become arrays, and non-literal expressions are kept as "${...}" strings, as in the Terraform JSON syntax.

Use the tool

Why this tool exists

Scripts, policy checks and documentation tools can read JSON easily, but Terraform is written in HCL. Reading .tf files from a script usually means installing a parser, and hand-converting a resource block is tedious. Paste the configuration here and get JSON in the structure Terraform itself accepts: resource.aws_instance.web style nesting, repeated unlabelled blocks as arrays, literals as values and references, function calls, conditionals and for expressions kept as "${...}" strings. Comments and heredocs are handled. Dynamic blocks are not expanded, so you see them as written. Because it parses your text locally, infrastructure code with internal names is not uploaded.

How to use it

  1. Paste your Terraform or HCL configuration into the input box.
  2. Set the indentation of the JSON output.
  3. Copy the JSON for your script, policy check or documentation.

Frequently asked questions

What structure does the JSON have?

It follows the Terraform JSON syntax: labelled blocks nest by label, such as resource, then type, then name. Blocks without labels become arrays of objects.

How are expressions handled?

Anything that is not a literal, such as var.region, a function call, a conditional or a for expression, is written as a "${...}" string, and is not evaluated.

Are dynamic blocks expanded?

No. The tool converts the syntax only and evaluates nothing, so dynamic blocks, count and for_each remain as written in the JSON and are not expanded into separate resources.

Can I convert the JSON back to HCL?

Yes, the YAML / JSON to Terraform HCL tool on this site writes HCL from the same JSON shape.

Tools often used together

  • Terraform HCL to YAMLParse Terraform / HCL2 configuration and print it as YAML using the same structure as the Terraform JSON syntax (labeled blocks nested, unlabeled blocks as lists, expressions as "${...}" strings).
  • YAML / JSON to Terraform HCLTurn YAML or JSON in Terraform JSON-syntax shape (resource: {type: {name: {...}}}, variable:, output:, locals:, provider:, terraform:) into HCL. Strings that are a single "${...}" expression are written unquoted, lists of mappings become repeated nested blocks, known block names (lifecycle, connection, ...) become blocks, other mappings (tags, etc.) stay attribute maps. Output is aligned like terraform fmt.
  • Terraform / HCL FormatterIndent HCL by nesting depth and align "=" in consecutive attribute lines (terraform fmt style). Heredocs untouched.
  • Terraform AWS ScaffolderScaffold providers, remote state, VPC, S3 bucket and EC2 instance blocks (formatted like terraform fmt).
  • JSON to YAMLConvert JSON to clean block-style YAML.
  • YAML to JSONConvert YAML to JSON. Supports maps, lists, flow style, | and > blocks, anchors/aliases/merge keys, multiple documents.
