Helm Chart Scaffolder

Enter a chart name, image and port and get the files for a minimal Helm chart: Chart.yaml, values.yaml, helpers, a Deployment, a Service and an optional Ingress.

Use the tool

Why this tool exists

helm create produces a large chart full of options you may not need, and you must have Helm installed to run it. For a small internal service, a trimmed-down chart with one Deployment, one Service and a few values is easier to read and maintain.

This scaffolder writes that smaller layout, with named templates in _helpers.tpl for labels and selectors, resource requests and limits in values, and an Ingress guarded by ingress.enabled. Copy each file into the right folder, then run helm lint. The text is created locally in your browser.

How to use it

  1. Enter the chart name (a lowercase DNS label), image repository, tag and container port.
  2. Set replicas and tick the Ingress template if you want one, with a host name.
  3. Copy each file block into your chart folder, then run helm lint and helm template.

Frequently asked questions

What if I leave the image tag blank?

The Deployment template falls back to the chart appVersion, so the tag follows the version you set in Chart.yaml. That is a common Helm convention.

Does it create a ZIP or folders?

No. It prints every file under a heading with its path. You create the files yourself and paste each section into them.

Why is the chart name restricted?

It must be a lowercase DNS label, using letters, digits and dashes, because the name flows into resource names that Kubernetes validates.

Is it production ready?

It is a minimal starting point. There are no probes, security context or autoscaling, so add them before running it in a shared cluster.
