Embedding Token & Cost Estimator

Paste a sample of your text and set the chunk size, overlap and document count to estimate tokens, number of chunks, embedding API cost and vector storage across popular embedding models.

Use the tool

Why this tool exists

Before you build a retrieval system, you need a rough idea of what indexing will cost and how big the vector store will be. The answer depends on the amount of text, how you split it into chunks, how much the chunks overlap and which model you use. Overlap in particular quietly multiplies the tokens you pay for.

This estimator takes a sample of your real text, works out its size, scales it to your document count and compares models side by side. Token counts are estimates from a character ratio, and the price table is a built-in snapshot, so enter your own price when it differs. Re-embedding runs and vector dimensions are included. The calculation is done in your browser and your text is not uploaded.

How to use it

  1. Paste a representative sample of your text.
  2. Enter the number of documents, the chunk size and the overlap.
  3. Adjust the characters-per-token ratio, vector dimensions and number of re-embedding runs, or enter a custom price.
  4. Compare the estimated cost and storage for each model.

Frequently asked questions

Why does overlap affect the cost?

Overlapping chunks repeat part of the text, so the same tokens are embedded more than once. A twenty percent overlap means roughly twenty percent more tokens, and the chunk count rises too.

Are the prices up to date?

The table is a snapshot that goes out of date as providers change their pricing. Enter your own price per million tokens for any real budget, and check the provider's pricing page.

How is it different from the embedding cost calculator?

This one starts from a text sample and chunk settings, so it works out tokens and chunks for you. The embedding cost calculator starts from a document count and an average size you already know.

Tools often used together

  • Embedding Cost CalculatorEstimate the cost of embedding a corpus: documents x average tokens (or characters / words), re-embedding runs, and vector storage size (dimensions x 4 bytes, plus HNSW overhead estimate). Prices are list prices per 1M tokens at the time of writing and change often: override with "Custom price" and check your provider. Token counts from characters are an approximation (about 4 characters per English token).
  • Text Chunk Splitter (RAG)Split text into overlapping chunks by characters or approximate tokens, preferring paragraph/sentence boundaries.
  • RAG Chunking VisualizerSee how a document splits into retrieval chunks: fixed window, sentence or recursive (paragraph, line, sentence, word) splitting with size and overlap. Chunks are color coded and overlaps highlighted (recursive and sentence modes overlap by whole segments, so overlap can be 0 when segments are large).
  • LLM API Cost CalculatorCompute request and monthly cost from tokens and your own per-million prices (prices change; enter current ones).
  • Embedding Vector SimilarityCompare embedding vectors you paste (JSON arrays or numbers, one vector per line): cosine similarity, dot product, Euclidean and Manhattan distance, plus a similarity matrix and best matches for several vectors. It does not create embeddings.
  • GPT Token Counter (cl100k + o200k, chat overhead)Exact token counts for text under cl100k_base and o200k_base side by side, plus an approximate chat-message overhead calculator (OpenAI cookbook rule: 3 tokens per message, +1 per name, +3 reply priming; use o200k_base for the GPT-4o family). Only OpenAI encodings (cl100k_base, o200k_base) are included. Claude, DeepSeek and Gemini tokenizers are NOT included (their vocabularies are not available offline): use the llm-token-estimator tool for approximate counts of those.
