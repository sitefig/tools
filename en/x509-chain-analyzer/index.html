Certificate Chain Analyzer (PEM Bundle, Signatures, Expiry, Hostname)

Debug "incomplete chain" and expiry problems by checking the certificates a server sends.

Use the tool

Why this tool exists

The analyzer parses each certificate, builds the chain from leaf to root by issuer and subject, and verifies each signature against its issuer's public key (RSA PKCS#1 v1.5, ECDSA and Ed25519; RSA-PSS is noted but not verified). It shows validity and days left, key type and size, signature algorithm, CA flag and path length, SAN, key usage and extended key usage, and warns about expired certificates, SHA-1 signatures, small RSA keys, non-CA issuers, a missing root or a hostname that is not covered. Tested on a generated three-level chain, with tampering detected.

It cannot check revocation (OCSP/CRL) or whether a root is trusted by a given system.

No data is sent anywhere: the work happens in your browser, so you can use it offline once the page has loaded.

How to use it

  1. Get the chain, for example with openssl s_client -showcerts.
  2. Paste the PEM blocks.
  3. Enter the hostname to test.
  4. Fix expired, missing or mismatched certificates.

Frequently asked questions

What does "stops at an intermediate" mean?

The root is not in the bundle, which is normal for servers; clients need it in their trust store.

Why is the order important?

Servers should send the leaf first, then intermediates; the tool re-orders by issuer when needed.

Does it check wildcard names?

Yes, a wildcard matches one label only.

Is my data sent anywhere?

No. Everything is processed in your browser, and the page makes no network requests with your input.
