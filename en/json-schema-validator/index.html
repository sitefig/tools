JSON Schema Validator

Validate a JSON document against a JSON Schema and see each failure listed with its path. It supports the common keywords, including anyOf, oneOf, allOf and local $ref.

Use the tool

Why this tool exists

A schema is only useful if you can check data against it. When an integration rejects a payload with a vague 400 error, or you are writing a schema and want to see how it behaves, you need a quick way to run both side by side and get readable messages.

Paste the schema in one box and the data in the other. Every failure is listed with its path, for example that age must be at most 150 or that a required key is missing, so you can fix them one by one. The tool covers the keywords most schemas use rather than every part of the specification, which is worth knowing for advanced schemas. Both documents stay in your browser and are not uploaded.

How to use it

  1. Paste the JSON Schema into the first box.
  2. Paste the JSON data you want to check into the second box.
  3. Read the verdict: Valid, or a list of errors with the path of each.
  4. Fix the data or the schema and run it again.

Frequently asked questions

Which keywords are supported?

Type, properties, required, items, enum, const, minimum and maximum, string length, pattern, uniqueItems, anyOf, oneOf, allOf, not and local $ref. It is a practical subset, not the entire specification.

Does it follow remote $ref links?

No. Only local references that start with #, such as #/definitions/cat, are resolved. A remote reference gives an error, so copy the referenced definitions into your schema.

Does it check format keywords?

Formats it knows, such as email, date, date-time and uuid, are checked with simple patterns. Unknown formats are ignored, so a pass does not prove a value is a real address.

What if the schema itself is wrong?

It reports parse errors for invalid JSON. It does not validate the schema against the meta-schema, so a misspelled keyword is simply ignored.
