SQL Index Advisor

Suggests CREATE INDEX statements from your CREATE TABLE schema and the SELECT, UPDATE and DELETE queries you run, using WHERE equality and range columns, join keys, ORDER BY and GROUP BY.

Use the tool

Why this tool exists

Slow queries are often missing an index, but guessing which one to add is a good way to create indexes that never get used and slow down writes. This tool reads the queries you actually run and proposes indexes from the pattern: equality columns first, then range columns, plus join keys and sort columns. It skips what already exists, such as primary keys, UNIQUE constraints and indexes you have defined. Add the schema for better column resolution. It is a static heuristic without table statistics, so it cannot know row counts or selectivity. Always confirm a suggestion with EXPLAIN on real data before adding it to production. Everything is analysed in your browser.

How to use it

  1. Paste your CREATE TABLE and CREATE INDEX statements into the first box.
  2. Paste the queries you run, separated by semicolons, into the second box.
  3. Read the suggested indexes, then test each one with EXPLAIN on real data.

Frequently asked questions

How does it choose the column order?

Equality conditions come first, then range conditions, then join, ORDER BY or GROUP BY columns where they can help. This follows the common rule of thumb for composite indexes.

Will it suggest indexes that already exist?

It skips columns already covered by a primary key, a UNIQUE constraint or an index in the schema you provide. Without a schema it cannot do this reliably.

Can I trust the suggestions?

They are a starting point. Without statistics the tool cannot judge selectivity, and an index also costs write speed and space. Confirm with EXPLAIN before adding it.

Does it handle every kind of query?

It handles common SELECT, UPDATE and DELETE patterns. Complex queries with subqueries or functions on columns may produce limited or no suggestions.
