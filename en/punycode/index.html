Punycode / IDN Converter

Convert domain names with accents or non-Latin letters into their xn-- Punycode form, or turn an xn-- name back into readable Unicode. Paste one domain per line.

Use the tool

Why this tool exists

The DNS only understands ASCII, so a name like münchen.de is actually stored as xn--mnchen-3ya.de. You see the xn-- form in DNS records, certificates, server logs, redirect rules and email headers, and you need it when configuring hosting for an international domain.

This converter applies the Punycode algorithm from RFC 3492 label by label, so each part of a domain between dots is handled separately and plain ASCII labels pass through. It does the work locally, which also makes it handy for checking suspicious lookalike domains without visiting them.

How to use it

  1. Enter one domain per line, for example münchen.de or xn--mnchen-3ya.de.
  2. Choose the direction: to punycode, or to unicode.
  3. Read the converted domains in the output, one per line.
  4. Copy them into your DNS settings, certificate request or redirect rules.

Frequently asked questions

What is the xn-- prefix?

It marks a domain label that contains non-ASCII characters encoded as Punycode. Browsers show the readable Unicode version, while DNS, certificates and email use the xn-- version.

Does it do full IDNA processing?

No. It applies plain Punycode to each label after Unicode normalisation (NFC) and lowercasing. It does not apply the full IDNA2008 mapping or validity rules, so confirm unusual characters with your registrar.

Can it help me spot lookalike domains?

Yes. Converting a suspicious domain to Unicode reveals whether it uses unusual characters, such as a Cyrillic letter that resembles a Latin one. It only converts, so it does not judge whether the domain is malicious.

Why is only part of my domain converted?

Only labels containing non-ASCII characters change. Labels like com or www are plain ASCII and are left as they are, so the output keeps the same dots.
