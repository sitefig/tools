Hash Compare

Paste two hashes and see whether they match. Case, spaces, colons and prefixes like sha256: are ignored, and the tool guesses the algorithm from the length.

Use the tool

Why this tool exists

Comparing two 64-character strings by eye is how mistakes happen. One is lowercase, the other uppercase with spaces from a PDF, and a changed character in the middle is easy to miss. You still need a reliable answer when you verify a download, a backup or a signature.

This tool cleans both values before comparing: it removes spaces, colons, dashes and prefixes such as 0x or sha256:, and ignores case. The comparison itself examines every character, so the verdict is exact. When the two differ, it reports the lengths and how many positions differ, which tells you whether the value was truncated or altered.

How to use it

  1. Paste the first hash, for example the one you calculated, into Hash A.
  2. Paste the second hash, for example the published one, into Hash B.
  3. Run the comparison.
  4. Read the MATCH or DIFFERENT verdict, the lengths and the likely algorithm.

Frequently asked questions

Which formatting differences are ignored?

Upper and lower case, spaces, colons and dashes, and leading prefixes such as 0x, sha256: or sha1=. The remaining hex digits are compared exactly.

How does it guess the algorithm?

By length: 32 hex characters suggests MD5, 40 SHA-1, 64 SHA-256, 96 SHA-384 and 128 SHA-512. Other lengths are reported as unknown. Several algorithms can share a length, so treat this as a hint.

What does the differing positions number mean?

When both hashes have the same length but differ, it counts the positions with different characters. A few differences point to a typing error, while about half of them suggests unrelated data.

Can it tell me if a file is genuine?

No, it only compares two strings. Use File Hash to compute the checksum of your file first, then compare it with the value from a trusted source.
