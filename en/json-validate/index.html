JSON Validator

Check if text is valid JSON. If it is, you get its root type, number of values, keys, maximum depth and size in bytes. If not, you get the line and column of the error.

Use the tool

Why this tool exists

Before you commit a config file, send a request body or import a data export, it is worth knowing for certain that it parses. A single trailing comma or a stray comment is enough to make a pipeline fail with a vague message.

This validator uses the same strict rules as a standard JSON parser and reports the precise line, column and offending character. When the document is valid it also summarises it: root type, count of values and keys, nesting depth and byte size. That quick overview helps you spot a payload that is unexpectedly large or deeply nested. It does not check a schema; for that, use the schema validator. Your text stays in the browser and is not uploaded.

How to use it

  1. Paste the JSON text into the input box.
  2. Read the verdict on the first line: Valid JSON, or an error with line and column.
  3. For valid input, check the root type, key count, depth and size shown below.
  4. Fix any error, then paste again to confirm.

Frequently asked questions

What rules does it use?

Strict JSON as defined by the standard. Comments, trailing commas, single-quoted strings, unquoted keys and values such as NaN or undefined are all reported as errors.

Does it validate against a schema?

No. It only checks that the text is syntactically valid JSON. To check types, required fields and ranges, use the JSON Schema Validator tool.

What do the statistics mean?

Total values counts every item in the document, object keys counts the keys of all objects, max depth is the deepest nesting level, and size is the number of UTF-8 bytes of your input.

Is my data sent anywhere?

No. Validation runs in your browser, so tokens or customer data in the pasted text are not uploaded.
