SQL Parameter Inliner (Fill ?, $1, :name Placeholders)

Paste a parameterised query and its values and get the full SQL as the database would see it.

Use the tool

Why this tool exists

Placeholders in the forms ?, %s, $1, :name and @name are replaced by literals from a JSON array or object. Strings are quoted with doubled single quotes (backslash escapes for MySQL), numbers and booleans are written plainly, null becomes NULL and arrays expand to comma lists for IN (...). Quoted strings and comments in the SQL are left untouched. The output was checked by running it in SQLite against bound parameters with tricky strings.

Use this to understand logs and to debug. Never build production queries by inlining values; keep using bound parameters.

No data is sent anywhere: the work happens in your browser, so you can use it offline once the page has loaded.

How to use it

  1. Paste the SQL with placeholders.
  2. Paste the values as JSON.
  3. Pick the dialect.
  4. Read or run the resulting SQL in a console.

Frequently asked questions

Is the output safe to run in production?

Not as a pattern. It is meant for inspection; bound parameters prevent injection.

How are arrays handled?

They become a comma-separated list for IN (?) placeholders.

Which dialects are supported?

Standard/SQLite, PostgreSQL and MySQL quoting.

Is my data sent anywhere?

No. Everything is processed in your browser, and the page makes no network requests with your input.
