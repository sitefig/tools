XSD Validator (Check XML Against an XML Schema)

Checks an XML document against an XML Schema and lists each problem with its path.

Use the tool

Why this tool exists

A schema error found late costs time. This page checks the common parts of XSD 1.0: sequence, choice and all content, minOccurs and maxOccurs, attributes, built-in types, restrictions, lists, unions and type extension.

It is a hand-written subset, not a full validator. Namespaces are ignored, identity constraints and other files (import, include) are not followed, and the page lists what it skipped. Verdicts matched lxml on 20 test documents; for final sign-off use your normal toolchain.

How to use it

  1. Paste the XML in the first box.
  2. Paste the XSD in the second box.
  3. Read the list of problems with their paths.
  4. Fix and run again.

Frequently asked questions

Is a Valid result final?

No. It is a good sign for common schemas. Confirm with xmllint or your build tool.

Which features are missing?

Namespaces, key, keyref, unique, substitution groups, import, include and XSD 1.1 assertions.

Why are error messages short?

They name the path and the first problem, such as an unexpected element or a value out of range.

Is my XML uploaded?

No.
