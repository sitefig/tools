Zod to JSON Schema

Paste Zod schema source and get JSON Schema. It is read by a small static parser, so your code is never executed.

Use the tool

Why this tool exists

Zod schemas are written for TypeScript, but OpenAPI generators, LLM tool definitions, form builders and docs tools all want JSON Schema. The usual route is a library call at runtime, which means setting up a project just to convert one file.

Paste the source and this tool reads the z.object, z.string, z.enum, z.union and similar calls without running them. It follows const references between declarations, so a schema built from smaller named parts works. Checks such as min, max, email, regex and int become keywords. Methods that need execution, such as refine or transform, are noted as ignored. It supports a common subset only, and unknown methods stop with a clear error instead of guessing.

How to use it

  1. Paste Zod source code, including the const declarations it refers to.
  2. The last schema in the text is used as the root.
  3. Copy the JSON Schema output into your tooling.

Frequently asked questions

Is my code executed?

No. The text is tokenised and parsed as data, and only the Zod method calls it recognises are translated. Nothing is evaluated, imported or sent anywhere.

Which Zod features are supported?

Primitives, literal, enum, array, tuple, record, union, intersection, object and strictObject, and chained checks like min, max, int, email, uuid, regex, optional, nullable, default and describe.

What about refine, transform and custom types?

Refinements and transforms are skipped because they cannot be expressed in JSON Schema. Unknown types or methods raise an error naming the one that is not supported.

How are optional fields treated?

A property is left out of the required list when it ends in optional, nullish or default. nullable makes the schema accept null as well.

Tools often used together

  • JSON Schema to ZodTurn a JSON Schema (draft-07 / 2020-12 subset: types, formats, bounds, enum/const, anyOf/oneOf/allOf, $ref to $defs) into Zod source code.
  • Zod Schema to TypeScript TypeStatically convert Zod schema source (z.object, z.string().min(), z.enum, z.union, z.array, z.record, optional/nullable/nullish, extend/merge, describe) into the equivalent TypeScript types, i.e. what z.infer would produce. The code is parsed, never executed. .transform() outputs and custom refinements are not inferable.
  • TypeScript Interface to Zod SchemaConvert TypeScript interfaces, type aliases and enums into Zod schemas (z.object, z.enum, z.union, z.tuple, z.record, optional/nullable, descriptions from JSDoc) plus inferred types. Same TypeScript subset as the TypeScript to JSON Schema tool.
  • TypeScript Interface to JSON SchemaConvert TypeScript interfaces, type aliases and enums to JSON Schema draft-07 (definitions + $ref). Supports optional props, unions, literals, tuples, arrays, Record, Date, index signatures, extends/intersections and JSDoc descriptions. Not supported: conditional/mapped types, keyof/typeof and most utility generics.
  • JSON Schema ValidatorValidate JSON data against a schema (type, properties, required, items, enum, min/max, pattern, anyOf/oneOf/allOf, local $ref).
  • LLM Tool Definition BuilderWrap a JSON Schema into OpenAI (Chat / Responses, strict mode) and Anthropic tool-definition JSON.
