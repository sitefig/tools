Responsive Breakpoint Previewer

Shows your HTML at several widths at the same time, such as 375, 768, 1024 and 1440 pixels. Each view is a scaled, sandboxed frame so you can compare how media queries change the layout.

Use the tool

Why this tool exists

Testing responsive CSS usually means dragging a window edge back and forth, or opening dev tools and switching device presets one by one. It is hard to compare the layouts together or to explain a difference to someone else.

Paste a snippet of HTML with its style block and the tool renders it in a row of frames, one for each width you list. Each frame has the real viewport width, so min-width and max-width media queries fire as they would in a browser, and the frames are scaled down to fit the page. Scripts are blocked, because each frame is sandboxed, so this is for layout and style checks only. Your code stays in your browser.

How to use it

  1. Paste your HTML and CSS into the input box.
  2. Enter the widths to test, separated by commas or spaces.
  3. Set the frame height in pixels.
  4. Compare the frames and adjust your CSS.

Frequently asked questions

Which widths are accepted?

Numbers from 100 to 4000 pixels, separated by commas or spaces. The default set is 375, 768, 1024 and 1440. Values outside the range are ignored.

Do media queries really trigger?

Yes. Each frame is rendered at its true width and scaled down afterwards with a transform, so width-based media queries evaluate against the real number, not the scaled size.

Why do scripts and links not work?

The frames are sandboxed with all permissions off, so JavaScript, forms and navigation are blocked. That keeps pasted code safe, but means you cannot test scripted behaviour here.

Can it load external stylesheets or images?

The snippet is rendered as given, so absolute URLs may load, but behaviour depends on the sandbox and your network. For reliable results, put the CSS in a style tag and use inline or data URL images.
