Code Security Scanner (Rule-Based, Local)

A quick, private lint for common security mistakes, each with its CWE identifier and a fix.

Use the tool

Why this tool exists

Line-by-line regular expressions look for dynamic code execution, HTML injection sinks, SQL built by string concatenation or formatting, shell execution from variables, unsafe deserialisation (pickle, yaml.load, unserialize, ObjectInputStream), weak hashes (MD5, SHA-1), insecure randomness, disabled TLS verification, hard-coded credentials, debug modes and unsafe C string functions.

There is no data-flow analysis, so expect false positives and misses. It is a pre-check before using proper static analysis such as Semgrep or CodeQL, and the code never leaves your browser.

No data is sent anywhere: the work happens in your browser, so you can use it offline once the page has loaded.

How to use it

  1. Paste a file or snippet.
  2. Run the scan.
  3. Read each finding with its CWE and suggested fix.
  4. Use a full SAST tool in CI for deeper coverage.

Frequently asked questions

Which languages are covered?

JavaScript/TypeScript, Python, PHP, Java, Go, Ruby and C patterns, plus language-independent rules.

Is a clean result safe?

No. It checks a short list of patterns on single lines only.

Does it upload my code?

No. The scan runs locally.

Is my data sent anywhere?

No. Everything is processed in your browser, and the page makes no network requests with your input.
