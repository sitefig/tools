## Verification

- Data read at the source (October 2026): WCAG 2.2 criteria (86, levels, new-in-2.2 flags) from w3.org/TR/WCAG22; WAI-ARIA 1.2 roles, attributes, required and prohibited attributes from w3.org/TR/wai-aria-1.2 (cross-checked against aria-query 5.1.3: 5 of about 90 roles differ, all explained by ARIA 1.1 vs 1.2 wording); autofill field names from the HTML Standard; speculation rules keys and eagerness values from the HTML Standard; throttling presets from devtools-frontend NetworkManager.ts; WCAG 1.4.12, 2.4.13 and 2.5.8 wording from the spec text.
- Oracles run: `lighthouse-report-viewer` against two real Lighthouse 12.2.2 reports (scores and metrics match); HAR totals against Python; image sizes against ffprobe for PNG, JPEG, GIF, WebP (lossy and lossless), BMP, AVIF, and EXIF orientation against PIL; contrast ratio against Python and the existing Contrast Checker; caption validator accepts files that ffmpeg round-trips; accessible names against Chromium's accessibility tree via Playwright getByRole; web vitals and text spacing bookmarklets executed in headless Chromium (CLS, overlay, toggle, computed spacing); srcset generator run in Chromium with a real JPEG.
- Not verified: EU Web Accessibility Directive statement wording and the EN 301 549 clause mapping (EUR-Lex was unreachable; stated on the pages); VPAT conformance term wording; vendor domain list is hand-made; plain-language word list is hand-made; TBT ms-per-KB default is an assumption; critical CSS "above the fold" is a heuristic; accname is a simplified implementation.
