# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A free, fully client-side toolbox (SEO, privacy, developer tools) with an optional browser-extension version later. The extension can fetch cross-origin data the web page can't, so keep tool logic separate from any fetch/IO layer. The tools are free standalone but are meant to give better results when used with Sitefig (see memory); never cripple a free feature to upsell.

Constraints: no backend, no network calls from tools (the only fetches are tools lazily loading same-origin data files from `data/`: tokenizer vocabularies, OCR, `sentiment.js` and the `ai-*` model weights from `gap5.js`; each file's source, licence and published hash are in `data/SOURCES.md` / `data/SOURCES-gap5.md`), and user input must never leave the browser. Anything needing an API, OAuth, an account or a server (backlinks, rankings, search volume, DNS/SSL lookups, AI models, currency rates) is deliberately skipped; each module lists its skips in a header comment.

## Commands

Dev-time deps only (`npm i`: Tailwind CLI); nothing from node_modules is shipped, tools stay dependency-free. Output is committed.

- `npm run build` = `build:css` (Tailwind -> `assets/site.css`) then `build:pages` (`scripts/build.mjs`: all HTML, sitemap, robots, llms.txt, 404, `assets/tools.json`, `assets/og.png`). Re-run after any change to tools, content, i18n, templates or CSS. It prints a content coverage report, duplicate title/description/h1 lists, the sensitive-tool list, and a loud warning while `siteUrl` is still `https://example.com`.
- `npm test` = `test/smoke.mjs` (tools in Node, via `src/tools/index.js`) + `test/sentiment.mjs` + `test/cli.mjs` (runner, CLI, MCP) + `test/pages.mjs` (built output: one h1, unique titles/descriptions, canonical, hreflang, JSON-LD, internal links, sitemap, no external origins).
- Serve: `python3 -m http.server 8765` (root-absolute URLs, so serve the repo root; ES modules need http, not file://).
- OAuth PKCE self-check: `node src/oauth.test.mjs`.

The smoke test skips `dom`, `file` and `render` tools; check those in a browser.

## Architecture

- One static page per tool: `/<lang>/<tool-id>/index.html`, plus `/<lang>/` (hub), `/<lang>/about/`, `/<lang>/accessibility/`, `/404.html`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`. `/index.html` redirects by `navigator.language` and maps legacy `/#tool-id` to `/<lang>/tool-id/`. Everything under `/<lang>/` is generated and wiped on each build: never edit it by hand.
- Manifest: `build.mjs` imports every `src/tools/*.js` (not `index.js`), skips a module that fails to import or is not an array, and writes `assets/tools.json`. `src/tools/index.js` is only used by the smoke test; a new module is picked up by the site automatically, add it to `index.js` too for tests. Categories are grouped after stripping trailing `+` (`Crypto+` -> `Crypto`).
- Site settings: `site.config.json` (siteName, siteUrl, langs, defaultLang, `sensitive` rules, schema.org category map). Every absolute URL derives from `siteUrl`.
- Page text: `content/<lang>/<tool-id>.json` (shape in `content/BRIEF.md`), `content/<lang>/_pages/about.json|accessibility.json`. A missing file falls back to the tool's own title/desc and same-category related tools. UI strings: `i18n/<lang>.json`, read by `build.mjs` (`t(key)`) and at runtime by `src/page.js` (`/i18n/<lang>.json`).
- Runtime (browser, plain ES modules, no build): `assets/theme.js` (blocking, sets `data-theme`, wires the toggle), `src/page.js` (imports ONLY the page's `src/tools/<module>.js`), `src/mount.js` (generic form/result UI + custom `render`), `src/urlstate.js` (query-string state), `src/a11y.js` (repairs UI generated by custom tools), `src/hub.js` (search over the static lists).
- Shareable state: `?i=`, `?i2=`..., option id = value (booleans `1`/`0`), `?z=` (deflate-raw base64url, used when the query would exceed 1800 chars), `?s=` (custom tools exposing `urlState`). Only values that differ from sample/defaults are written. Tools flagged `sensitive` (rules in `site.config.json`, reviewed list printed by the build) never auto-write input to the URL; only the explicit "Copy share link" does, with a warning.
- CSS (CUBE CSS + Tailwind v4): `styles/main.css` declares `@layer theme, reset, tokens, global, compositions, utilities, blocks, exceptions` and imports `tokens.css` (all colour/type/space values, light+dark; these are the Sitefig design system from https://sus.bot: yellow `--signal` primary actions, Atkinson Hyperlegible fonts self-hosted in `assets/fonts/`; the link back to the parent brand comes from `parent` in `site.config.json`), `global.css` (bare elements), `compositions.css` (wrapper, stack, cluster, repel, sidebar, switcher, grid, cover), Tailwind utilities (class names are scanned from `scripts/*.mjs` and `src/*.js` only), `blocks.css` (components; `.tool-panel__custom` carries the legacy class names that custom tools use), `exceptions.css` (data-attribute states). Both themes were checked for WCAG AA contrast; if you change tokens, re-check. Accessibility target: WCAG 2.2 AA (see TOOLS.md for the tool-author contract and `content/en/_pages/accessibility.json` for the public statement, which must stay truthful: re-audit before changing its conformance wording). System fonts only.
- Tool modules from the owner's idea list `free-browser-tools.md` are `src/tools/new01.js`..`new22.js` (one per batch; decision table per batch in `peerreview/new-list/NN.md`: covered / built / skipped with reasons). `gap1`..`gap6` came from the peer-site audits (`peerreview/gap-audit.md`, `feature-audit.md`, `skip-review.md`). Bundled public data files are listed with source, licence and hash in `data/SOURCES*.md`.
- Scripts / MCP: `cli/runner.mjs` (shared Node runner over the same `tool.run()` the pages use; file reads confined to cwd + `FT_ALLOWED_DIRS`), `cli/ft.mjs` (CLI: search, list, info, run), `cli/mcp.mjs` (stdio MCP server with four meta-tools, runs each call in `cli/worker.mjs` with a timeout). No second implementation of any tool: add logic to the tool module, never to `cli/`. Rationale and setup in `docs/local-mcp.md`; `test/cli.mjs` runs every runnable tool through the runner and exercises the CLI and the MCP protocol.
- Tools take pasted HTML/headers/robots text rather than URLs because a web page can't fetch other sites (CORS). A future extension layer would supply fetched content to the same tools.
- `src/oauth.js`: generic Authorization Code + PKCE helper (in-memory tokens, no refresh); not wired into the UI. The extension should use `chrome.identity.launchWebAuthFlow` instead.
- `peerreview/landscape.md`: competitor survey that the tool list came from.

## How to add

- A tool: add an object to a `src/tools/*.js` array (contract in `TOOLS.md`), write `content/en/<id>.json`, `npm run build`, `npm test`. Tool ids must not be `about`, `accessibility` or `assets`.
- A language: add `i18n/<lang>.json` (copy `en.json`), `content/<lang>/_pages/*.json`, `content/<lang>/<tool-id>.json` files, put the code in `langs` and `locales` of `site.config.json`, build. A non-default language only gets pages for tools that have a content file; hreflang alternates are emitted only for pages that exist.
